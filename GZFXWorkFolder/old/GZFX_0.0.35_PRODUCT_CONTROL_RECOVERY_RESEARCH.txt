2. CONTROL FAILURE — ARCHITECTURE DECISION
======================================================================

Do NOT remove AV2 and fall back to the older scene-effects stack.

Reason:
    GZFX2 proves AV2/Wave3 are healthy and zero-skip on the current renderer.
    AV2 is the stronger current foundation.
    Regressing to the old stack would throw away the current temporal/native
    input architecture merely to make old sliders move.

Do NOT simply delete scene_effects' AV2 ownership guard and run everything.

Reason:
    that would reactivate the legacy horizon AO on top of AV2 and can double
    ambient occlusion, reintroducing the dark/banding behavior the project has
    repeatedly fought.

Selected architecture:

    AV2 remains the owner of Horizon/HBAO visibility.
    SceneEffects regains AmbientContact and LocalGlow only.
    Legacy ambient-depth stack may run only as indirect/SSIL under AV2 ownership.
    When AV2 does not own a mode, legacy AO remains available as fallback.

This reconnects current controls while preserving current renderer ownership.

3. AV2 LIVE SETTING BINDING
======================================================================

Current AV2 shader parameters are mostly hard-coded.

0.0.35 must bind:

HorizonOcclusion Enabled
    false:
        do not replace Skyrim stock AO with AV2
        preserve stock AO
        do not compute AV2 when no capture/debug reason requires it

    true:
        AV2 compute/injection active

HorizonOcclusion Strength
    Current default:
        0.25

    Existing AV2 output has an implicit baseline strength of 1.0.

    To avoid changing the accepted baseline merely by wiring the control, use a
    normalized multiplier anchored at the existing default:

        outputMultiplier =
            clamp(setting / 0.25, 0.0, 4.0)

    default 0.25 -> 1.0 existing visual baseline
    0.0 -> neutral GZFX AO contribution
    1.0 -> clearly stronger 4x occlusion response

    This gives the slider a large, testable range without silently changing the
    default look.

HorizonOcclusion RadiusPixels
    Current default:
        28

    Existing AV2 world radius:
        240

    The current menu uses a pixel-named legacy value while AV2 operates in
    reconstructed view/world distance. Until the UI is redesigned, preserve the
    old control name but use a documented anchored conversion:

        RadiusWorld =
            clamp(
                240 * RadiusPixels / 28,
                bounded minimum,
                bounded maximum)

    default 28 -> 240 existing AV2 baseline.

    This is an explicit compatibility mapping, not a claim that world units and
    pixels are physically equivalent.

HorizonOcclusion Quality
    Existing default:
        2

    Existing AV2:
        slices=3
        steps=6

    Use real workload tiers:

        0 -> 2 slices x 4 steps
        1 -> 3 slices x 4 steps
        2 -> 3 slices x 6 steps   [current baseline]
        3 -> 4 slices x 8 steps

    Therefore the quality control changes actual GPU work, not merely a label.

4. AMBIENT CONTACT / LOCAL GLOW RECOVERY
======================================================================

Current scene_effects already contains shader implementations and settings
bindings for:

    AmbientContact Strength
    AmbientContact RadiusPixels
    LocalGlow Enabled
    LocalGlow Strength
    LocalGlow Threshold
    LocalGlow RadiusPixels

The entire path is currently bypassed because AV2 owns modes 1/2.

0.0.35 must refactor this into independent responsibilities:

    bool wave4OwnsAo =
        ambient_visibility_v2::OwnsDevelopmentMode(mode)

    DO NOT early-return solely because wave4OwnsAo.

Instead:

    1. optionally run legacy ambient-depth for indirect bounce with AO disabled
       when AV2 owns AO;
    2. run SceneEffects AmbientContact/LocalGlow using the current scene color;
    3. preserve current mode split/full behavior.

This turns those menu controls back into real GPU constants without double-HBAO.

======================================================================
5. SSIL / INDIRECT BOUNCE RECOVERY
======================================================================

The current repo still contains the legacy ambient-depth stack.

Its current implementation already:
    reads IndirectBounce Enabled
    reads IndirectBounce Strength
    reads IndirectBounce RadiusPixels
    reads IndirectBounce Saturation
    uses depth/scene color
    builds spatial indirect signal
    composites indirect into scene color
    has AO and indirect enable flags in its GPU constants

The problem is reachability, not total absence.

Add an explicit policy to ambient_depth::Apply:

    allowAo

When AV2 owns AO:
    allowAo=false
    parameters.aoEnabled=0
    indirect path remains settings-controlled

When AV2 does not own AO:
    allowAo=true
    legacy behavior remains available

The composite shader is already neutral when AO input is disabled:
    AO output is zero
    visibility multiplier becomes 1
    indirect contribution remains independently gated by IndirectEnabled.

Therefore the current SSIL controls can be recovered without layering old AO on
top of AV2.

This is a recovery step, not a claim that the legacy spatial SSIL is the final
ENB-class indirect-lighting solution.

7. ROUTINE TELEMETRY REDESIGN
======================================================================

GZFX2 wrote:
    276,115,361 bytes

with:
    411,890 detailed pipeline rows

The dominant files were four approximately 64 MiB pipeline_runs CSV segments.

Current telemetry code automatically enables detailed late-pipeline collection
every world frame from:
    AfterAmbientScreenSpaceComposite
through:
    BeforeOriginalPresent

That was appropriate for cartography.
It is no longer appropriate for routine product field validation.

Selected 0.0.35 policy:

DEFAULT FIELD MODE:
    compact frames
    seconds
    stage boundaries
    semantic summaries
    transitions
    ownership/timing summaries
    renderer/input/effect diagnostics

NO automatic detailed pipeline_runs window.

FORENSIC MODE:
    opt-in through environment/test flag or explicit future diagnostic request
    bounded late-detail window only
    segment size below repository upload ceiling
    never continuous multi-thousand-frame broad tracing by default

0.0.35 implementation:
    add g_lateDetailEnabled
    default false
    only start the automatic late detail gate when explicit
        GZFX_TELEMETRY_LATE_DETAIL
    full-pipeline test override remains available
    preserve test harness behavior where explicitly requested

Expected result:
    routine GZFX field ZIPs return to small single-archive scale.

This is not an optimization campaign.
It is evidence-scope correction after renderer cartography closure.
