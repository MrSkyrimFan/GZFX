======================================================================
2. SKSE INTEGRATION
======================================================================

GZFX now exports:

    SKSEPlugin_Version
    SKSEPlugin_Preload
    SKSEPlugin_Load

SKSEPlugin_Version:

    plugin version 31
    exact Skyrim runtime compatibility 1.7.104
    minimum SKSE 2.3.1

SKSEPlugin_Preload:

    rejects editor / wrong runtime / too-old SKSE
    arms the existing GZFX D3D11/DXGI import lifecycle probe
    keeps the plugin resident on the supported runtime after hook attempt

SKSEPlugin_Load:

    acquires plugin handle
    acquires Messaging interface
    acquires Trampoline interface
    registers an SKSE lifecycle listener
    initializes the existing GZFX runtime
    arms process-lifetime ExitProcess telemetry closure
    records deterministic bridge evidence

Current SKSE startup source was independently checked:

    Preload runs before global initializers
    Load runs immediately after global initializers
    Load occurs before normal WinMain execution continues

This gives GZFX an early observation point without a local system-name proxy DLL.

======================================================================
3. DEPENDENCY / LICENSE BOUNDARY
======================================================================

GZFX does NOT redistribute SKSE runtime binaries.

The repo pins the required public ABI/runtime contract and implements only the
small SKSE interface surface GZFX consumes.

Current CommonLibSSE-NG 15.x was NOT linked because it is GPL-3.0-or-later and
the owner has not authorized converting GZFX to a GPL-compatible licensing
model.

GZFX therefore remains:

    SKSE-hosted for loading/lifecycle
    GZFX-owned for renderer/D3D11/DXGI/signature machinery

======================================================================
5. PROCESS LIFECYCLE
======================================================================

The proven ExitProcess-driven telemetry closure moved out of d3d11.dll and into
GZFX.dll.

A first implementation armed that process-lifetime hook from generic
GZFX_Initialize. CI exposed the flaw immediately: unit harnesses legitimately
FreeLibrary(GZFX.dll), leaving ExitProcess pointed into an unloaded module.

Repair:

    process-lifetime hook ownership moved to SKSEPlugin_Load only

This matches real deployment, where SKSE owns the plugin for process lifetime.

GZFX_Shutdown is idempotent.
