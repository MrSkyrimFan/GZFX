2. PRE-REPAIR FORENSICS
======================================================================

Verified exports included:

    SKSEPlugin_Version
    SKSEPlugin_Preload

    GZFX_Initialize
    GZFX_Shutdown

The custom GZFX SKSE ABI was independently checked against official SKSE 2.3.1
source for Skyrim 1.7.104:

    SKSEInterface layout matched
    Messaging interface v2 matched
    Trampoline interface v1 matched
    SKSEPluginVersionData size/layout matched
    runtime 1.7.104 packed value matched 0x01070680
    SKSE release index matched 75
    explicit compatibleVersions={1.7.104,0} is accepted

Therefore the field failure was not explained by missing exports or an obvious
SKSE ABI/version declaration error.

Three real-runtime risks/defects remained:

1. SKSEPlugin_Preload performed SkyrimSE.exe PE/IAT rewriting before global
   initializers even though SKSE documents Preload as capability-limited.

2. The shipped DLL depended on dynamic Microsoft VC runtime DLLs
   (MSVCP140/VCRUNTIME140 family), which CI runners contain but a clean game
   machine may not.

3. CommonLibSSE-GG was linked but GZFX bypassed its supported SKSE::Init
   initialization contract.

======================================================================
3. FINAL REPAIR
======================================================================

A. PRELOAD IS NOW NON-INVASIVE

SKSEPlugin_Preload now only:

    validates the exact supported SKSE/runtime pair
    records that preload was entered in process state
    returns true

It does NOT:

    parse SkyrimSE.exe imports
    VirtualProtect or rewrite D3D/DXGI IAT slots
    initialize CommonLib
    initialize the GZFX renderer
    perform normal runtime filesystem setup

B. GRAPHICS ARM MOVED TO NORMAL SKSE LOAD

SKSEPlugin_Load now owns:

    ArmEarlyGraphicsBootstrap()
    GZFX_Initialize()
    CommonLib initialization
    process-lifetime telemetry closure

This preserves the official SKSE front door while avoiding invasive work in the
capability-limited preload phase.

C. COMMONLIB NOW USES ITS SUPPORTED INITIALIZER

The bridge now calls:

    SKSE::Init(
        reinterpret_cast<const SKSE::LoadInterface*>(skse),
        false)

after exact runtime and Address Library prerequisites pass.

CommonLib API readiness is recorded and DataLoaded singleton binding is gated on
that readiness.

D. MSVC CRT IS STATIC

Build configuration now uses the static MSVC runtime and vcpkg triplet:

    x64-windows-static

The produced GZFX DLL is no longer dependent on:

    MSVCP140.dll
    VCRUNTIME140.dll
    VCRUNTIME140_1.dll
    api-ms-win-crt-* runtime DLLs

Normal Windows/D3D system dependencies remain.

E. NEW PE LOAD CONTRACT

CI now inspects the actual produced GZFX.dll and fails if:

    required SKSE/GZFX exports disappear
    dynamic Microsoft C/C++ runtime dependencies reappear
