The owner performed the first real-Skyrim test of the 0.0.32 SKSE + CommonLib

claiming a single unsupported cause.

======================================================================
2. 0.0.33 LOADER REPAIR
======================================================================

SKSEPlugin_Preload is now deliberately non-invasive.

Preload performs only:
    exact compatibility validation
    preload-entered state
    return true

Preload no longer:
    parses SkyrimSE.exe imports
    rewrites D3D11/DXGI IAT slots
    VirtualProtects Skyrim import entries
    initializes CommonLib
    initializes renderer/runtime subsystems

Renderer observation now arms during normal SKSEPlugin_Load, before
GZFX_Initialize.

This keeps official SKSE as the front door while removing invasive executable
mutation from SKSE's capability-limited preload phase.

======================================================================
3. COMMONLIB INITIALIZATION REPAIR
======================================================================

0.0.32 linked CommonLib but bypassed its supported SKSE initialization path.

0.0.33 adds:
    InitializeSkseInterface(raw SKSE interface)

Real Skyrim path:
    InitializeModule
    validate exact 1.7.104 runtime
    verify Address Library file exists
    SKSE::Init(reinterpret_cast<const SKSE::LoadInterface*>(raw), false)
    mark CommonLib SKSE API ready

DataLoaded singleton binding is now gated on successful CommonLib SKSE API
initialization.

The CommonLib bridge remains read-only in this wave.
