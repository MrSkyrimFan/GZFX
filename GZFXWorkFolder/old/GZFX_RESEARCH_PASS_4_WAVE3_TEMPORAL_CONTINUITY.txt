======================================================================
1. EXECUTIVE CONCLUSION
======================================================================

The 0.0.21 field failure is narrow and repairable.

No new broad renderer cartography is required.

The R32 hierarchy, native motion, AfterOpaqueWorldMRT insertion, owned command
lists, state isolation and foundation stage scheduler should remain intact.

The main correction is:

DO NOT USE PHYSICAL NATIVE RESOURCE GENERATION AS TEMPORAL SEMANTIC CONTINUITY.

NORMAL_MASK_CURRENT is a logical current-frame semantic whose physical backing
resource is expected to ping-pong.

Temporal history is GZFX-owned.

Therefore the prior frame does not require the same physical native normal
texture to remain bound or even to remain the current backing resource.

What temporal reuse requires is:

- a valid current NORMAL_MASK_CURRENT semantic;
- the same semantic contract / layout;
- the same renderer device/surface geometry;
- continuous frames;
- valid camera continuity;
- valid environment/history lifecycle.

The current physical ID may change without invalidating GZFX history.

The repair should replace hard reset checks on:

    depth semanticGeneration
    motion semanticGeneration
    normal semanticGeneration

with stable semantic-contract tokens.

The CameraZ diagnostic must also stop treating all positive values as
geometry.

Public reconstructed Skyrim CameraZ code explicitly clamps linearized depth to
a positive far value, so background can be positive.

Finally, Shift+Numpad5 must become one authoritative request path rather than
two timing-sensitive keyboard polls.

======================================================================
2. WHY PHYSICAL GENERATION IS THE WRONG TEMPORAL TOKEN
======================================================================

Current Semantic Authority generation means:

    backing resource identity changed
    OR
    semantic confidence was promoted

It is a physical/authority bookkeeping generation.

That is valuable for:

- SRV cache invalidation;
- COM resource lifetime;
- diagnostics;
- proving identity changes.

It is not equivalent to:

    "the logical meaning of this semantic changed."

Field proof:

NORMAL_MASK_CURRENT alternates between two verified physical resources on
consecutive frames.

Example:

4733:
    0x1AAFA5D2060

4734:
    0x1AAFA5CFE30

4735:
    0x1AAFA5D2060

The semantic remains:

    NORMAL_MASK_CURRENT

The dimensions remain:

    2560x1440

The format remains:

    R8G8B8A8_UNORM

The renderer stage remains:

    AfterOpaqueWorldMRT

The semantic is current and valid on every frame.

Therefore the logical contract is continuous.

Resetting temporal history on this expected backing swap is categorically
wrong.

======================================================================
3. TEMPORAL HISTORY IS INDEPENDENT OF NATIVE RESOURCE IDENTITY
======================================================================

Wave 3 stores its own previous geometry:

    previous linear depth
    previous world normal
    previous confidence
    previous camera snapshot

The next frame never needs the prior native normal resource.

It only needs the CURRENT native normal texture to produce CURRENT geometry.

Likewise:

- prior native motion texture is not history;
- prior native main-depth texture is not history.

Thus a native resource identity replacement with the same valid semantic
contract does not by itself invalidate GZFX-owned history.

This is especially important for ping-pong render targets.

4. REQUIRED CONTINUITY MODEL
======================================================================

Keep:

    ResourceInfo.generation

as the physical semantic-resource generation.

Add/use a separate production concept:

    SemanticContractToken

A token describes the shape/meaning contract expected by the production
consumer.

Recommended token inputs:

    semantic enum
    resource dimension
    width
    height
    mip count
    array size
    sample count
    resource format
    typed SRV format

Device and surface generations remain separate global lifecycle tokens.

The token intentionally excludes:

    physical COM identity
    physical ResourceInfo.generation

For Wave 3 native geometry inputs:

MAIN_DEPTH_CURRENT contract:

    Texture2D
    width x height
    mip 1
    array 1
    samples 1
    resource R24G8_TYPELESS
    view R24_UNORM_X8_TYPELESS

MOTION contract:

    Texture2D
    width x height
    mip 1
    array 1
    samples 1
    R16G16_FLOAT

NORMAL_MASK_CURRENT contract:

    Texture2D
    width x height
    mip 1
    array 1
    samples 1
    R8G8B8A8_UNORM

A physical ping-pong preserves the token.

A true layout change changes the token.

======================================================================
5. RESET RULE AFTER THE REPAIR
======================================================================

GLOBAL HARD RESET remains required for:

1. first valid frame
2. frame gap
3. device generation change
4. surface generation change
5. render dimensions change
6. required semantic contract token change
7. camera generation change
8. invalid/missing required input
9. environment/load discontinuity
10. camera cut
11. runtime resource/shader rebuild that changes temporal signal
12. explicit developer reset

GLOBAL HARD RESET is NOT required merely because:

    MAIN_DEPTH_CURRENT physical generation changed
    MOTION physical generation changed
    NORMAL_MASK_CURRENT physical generation changed

when the current semantic is valid and its contract token is unchanged.

======================================================================
6. WHY REMOVING THE PHYSICAL GENERATION CHECK IS SAFE
======================================================================

The production broker already fails closed each frame.

It checks:

- Semantic Authority says the requested semantic is current at the requested
  frame/stage;
- the live physical texture identity matches the authority's CURRENT identity;
- dimensions are correct;
- format is correct;
- sample count is correct;
- the typed SRV can be created/acquired.

Therefore a stale or incorrect physical resource cannot silently satisfy the
current input bundle.

If a semantic disappears for one frame:

    AcquireGeometryInputs fails
    ->
    Wave 3 invalidates history

If the renderer changes dimensions:

    dimensions/surface lifecycle reset

If the D3D device changes:

    device-generation reset

If the resource changes physical backing while preserving the same semantic
contract:

    broker reacquires the correct current SRV
    ->
    temporal history may continue safely.

11. CAMERAZ BACKGROUND - PUBLIC SOURCE PROOF
======================================================================

Community Shaders' reconstructed Skyrim:

    ISSAOCameraZ.hlsl

computes:

    ClippedDepth =
        clamp(
            g_ClipInfos.x /
            (g_ClipInfos.y * rawDepth + g_ClipInfos.z),
            0,
            g_ClipInfos.w)

This is decisive for the field diagnostic issue.

STOCK_CAMERAZ is not encoded with:

    background = 0

Its output is clamped to a positive maximum value.

Raw/background device depth can therefore become a positive far/clipped depth.

That exactly matches the field evidence:

    both_background=0

and white "stock-only" sky regions.

The current comparison's:

    stockValid = stockDepth > 0

is invalid as a geometry predicate.

======================================================================
12. CORRECTED CAMERAZ DIAGNOSTIC
======================================================================

Keep CameraZ for:

    numerical scale/sign comparison

Do NOT use positive CameraZ alone for geometry validity.

For an immediate bounded repair, determine the stock far/background sentinel
from the captured hierarchy itself.

Because the CameraZ shader clamps to a maximum:

    stockFar =
        maximum finite STOCK_CAMERAZ mip0 value

Define background with a small tolerance around that clamped maximum.

Example engineering predicate:

    epsilon =
        max(stockFar * 1e-5, 1e-4)

    stockBackground =
        abs(stockDepth - stockFar) <= epsilon

    stockGeometry =
        stockDepth > 0 &&
        !stockBackground

Log:

    stock_far_value
    stock_background_pixels
    stock_geometry_pixels

This will immediately stop broad sky from being mislabeled as stock-only
geometry.
