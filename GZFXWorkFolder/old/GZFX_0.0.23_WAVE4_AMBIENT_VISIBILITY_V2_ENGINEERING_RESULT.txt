======================================================================
6. AMBIENT VISIBILITY ALGORITHM
======================================================================

The implementation is an independently authored GTAO-inspired horizon
visibility pass informed by:

- Activision GTAO research;
- MIT XeGTAO concepts;
- NVIDIA SAO/HBAO public research;
- GZFX renderer evidence.

No GPL Community Shaders implementation was copied.

Primary algorithm properties:

    full resolution

    current positive view-space depth from GZFXSceneDepthHierarchy

    native Skyrim view-space normal decode

    camera projection/inverse reconstruction

    world-space radius

    projected screen-space sampling radius

    procedural per-pixel/frame low-discrepancy noise

    directional horizon slices

    opposite-side horizon search

    hierarchical mip selection from sample offset

    world-radius rejection/falloff

    analytic GTAO-style normal/horizon integration

    scalar visibility [0,1]

    background visibility = 1

Initial production constants:

    radius world = 240

    falloff final fraction = 0.35

    sample distribution power = 2

    visibility power = 1

    slices = 3

    steps per slice = 6

These are field-build engineering seeds.

They are not yet exposed as a large user-facing tuning surface.

======================================================================
7. FULL-RESOLUTION BASELINE
======================================================================

Wave 4 intentionally begins at full active renderer resolution.

No half-resolution shortcut was introduced.

Reasons preserved from research:

- the old half-resolution prototype flickered/crawled;
- Wave 3 gives a high-quality full-res hierarchy;
- the project quality target is ENB-class-or-better;
- there was no measured requirement forcing a resolution compromise before
  the real production effect existed.

The field gate will determine whether the full-res cost is acceptable.

======================================================================
8. DEPTH HIERARCHY REUSE
======================================================================

Wave 4 does not create another depth hierarchy.

It directly samples:

    Wave3 FrameView.depthHierarchy

This is the field-proven:

    R32_FLOAT
    full mip chain
    post-opaque
    positive view-space depth

Hierarchy mip selection is based on sample pixel distance so larger-radius
samples can use coarser depth without rebuilding or generating new mips.

======================================================================
9. NATIVE NORMALS
======================================================================

Wave 4 uses:

    NORMAL_MASK_CURRENT.RG

with the already-proven Skyrim native normal decode.

It does not use RT2.B/A semantics.

It does not silently fall back to depth-derived normals.

If required current native geometry input cannot be acquired:

    Wave 4 does not overwrite stock AO.

Stock Skyrim AO remains the fail-soft path.

======================================================================
10. SPATIAL FILTER
======================================================================

Raw visibility is filtered full-resolution with two separable bilateral
compute passes.

Horizontal:

    5 taps

Vertical:

    5 taps

Weights include:

    spatial distance
    relative view-depth similarity
    native-normal agreement

Background does not intentionally bleed into geometry.

This replaces the old prototype's broad unstable blur behavior.

======================================================================
11. TEMPORAL SIGNAL HISTORY
======================================================================

Wave 4 owns only signal history:

    VisibilityHistory[2]
    R16_FLOAT

It does NOT create another geometry-history system.

Inputs:

    current spatial visibility
    native motion
    Wave 3 geometry confidence
    Wave 3 reprojection/accepted mask
    previous Wave 4 visibility
    Skyrim current/previous dynamic-resolution ratios

Reprojection remains:

    previousUV =
        currentUV +
        nativeMotion.xy

Previous history uses the previous dynamic-resolution ratio.

Previous AO is accepted only where Wave 3 geometry reprojection is valid.

A current 3x3 visibility neighborhood clamps the previous signal before blend.

Temporal weight responds to:

    Wave 3 confidence
    motion magnitude

Wave 4 history resets when:

    frame continuity breaks
    Wave 3 history generation changes
    runtime resources rebuild

Expected physical native-normal ping-pong therefore does not create a second
history discontinuity model.

======================================================================
12. STOCK SKYRIM LIGHTING INTEGRATION
======================================================================

This is the most important Wave 4 architectural change.

The previous prototype approach modified HDR scene color directly.

Wave 4 does not.

Renderer cartography proved:

    stock temporal RawAO
    ->
    stock AO filter temp
    ->
    stock SAO_FILTERED
    ->
    stock RawIndirect
    ->
    stock Ambient Screen-Space Composite consumes:
        RAW_INDIRECT
        SAO_FILTERED
        depth
        normal
        auxiliary/lighting resources
    ->
    MAIN_HDR

Wave 4 computes its visibility earlier.

Then at:

    AfterStockAO

it identifies the exact current:

    AOFiltered / SAO_FILTERED

resource through Semantic Authority plus current RT0 identity validation.

Required contract:

    current frame
    full current dimensions
    R8G8B8A8_UNORM
    sample count 1
    UAV bind capability

Only after all checks pass does GZFX replace the stock AO content.

The stock RawIndirect pass still executes.

The stock Ambient Screen-Space Composite still executes.

Skyrim therefore applies GZFX ambient visibility in Skyrim's own ambient
lighting domain.

13. MODE 1 - STAGE-CORRECT SPLIT
======================================================================

Development Mode 1 now means:

    SPLIT AMBIENT VISIBILITY

Before replacement:

    stock SAO_FILTERED is copied to a GZFX-owned stock reference texture.

    left half:
        original stock AO

    right half:
        GZFX Ambient Visibility v2

The resulting split is then consumed by Skyrim's normal ambient composite.

This is not a late backbuffer split.

It is a same-lighting-domain stock/GZFX comparison.

14. MODE 2 - FULL REPLACEMENT
======================================================================

Development Mode 2 now means:

    FULL AMBIENT VISIBILITY

    float4(

inside the active region.

Dynamic-resolution inactive area is kept unoccluded.

Skyrim then performs the normal downstream ambient composite.

15. STOCK FALLBACK

    Wave 3 FrameView

    shader compilation
    current-frame visibility production
    current SAO_FILTERED semantic

then:

    Wave 4 leaves stock SAO_FILTERED untouched.

The stock Skyrim lighting path continues.

No guessed substitute is written.

======================================================================
16. RENDERER STATE ISOLATION
======================================================================

Wave 4 uses its own deferred context.

Compute work is finished into command lists and executed through:

    Renderer Execution Service
    ExecuteOwned(..., TRUE)

New owned pass classes:

    Wave4AmbientVisibility
    Wave4AmbientInjection

The injection command list explicitly unbinds outputs in its own deferred
state before binding SAO_FILTERED as UAV.

Immediate Skyrim state is restored after command execution.

GZFX-owned work remains distinct from opaque Skyrim command-list evidence.

======================================================================
17. CURRENT CAMERA HANDOFF
======================================================================

The AfterStockAO injection needs current camera dynamic-resolution parameters.

Wave 4 does not heuristically reacquire a random 720-byte buffer later.

At AfterOpaqueWorldMRT, Native Input Broker already supplies the validated
current camera buffer.

Wave 4 retains one AddRef'd reference for the current computed frame and uses
that exact camera buffer when packing SAO_FILTERED later in the same frame.

Frame mismatch fails soft.

This preserves the production ownership model established by Wave 3.

======================================================================
19. LEGACY CI HARNESS ISOLATION
======================================================================

Initial Wave 4 CI correctly suppressed old mode1/2 effects everywhere.

That caused historical regression harnesses, which intentionally expect the
legacy prototype behavior, to fail.

This was a test-environment ownership collision rather than a product
rendering defect.

A bounded test-only rule was added:

If:

    GZFX_TEST_OUTPUT_ROOT is set

and:

    GZFX_TEST_WAVE4_ACTIVE is NOT set

then Wave 4 stays dormant and does not claim modes 1/2.

The dedicated Wave 4 integration harness explicitly sets:

    GZFX_TEST_WAVE4_ACTIVE=1

Result:

- historical harnesses continue proving legacy behavior;
- Wave 4 integration harness proves the new production behavior;
- real Skyrim has no test-output environment and therefore runs Wave 4
  normally.

Visible-pass legacy mode text is similarly preserved only in legacy harness
mode.
