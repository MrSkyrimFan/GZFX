SOURCE RESEARCH — UI/PRESETS
  Settings descriptor drives INI, slider range, label and persistence.
  ProductPreset's numeric slider changes the enum but does not apply
  preset fields until a separate ApplyPresetAction; this contradicts user
  expectation and should apply on selection.
  Preset loading copies g_values rather than Values{} (neutral/default
  base), preserving previous extreme ambient settings. Start preset from
  Values{} instead, preserve user-selected quality and custom-slot metadata.
  Reset Defaults must reset ONLY active Values to explicit fresh defaults,
  persist them and increment revision, WITHOUT removing CustomN.* sections.
  Existing custom Save/Load continues to operate across reset/relaunch.
  NormalizeRelations must map legacy developer modes 1/3/4 to normal full ON.
  All visible transitions should have test coverage.

INTEGRATED NEW FEATURES — SHARED PSComposite, NO EXTRA PASSES
  1. Shadow recovery (0 neutral): small luminance-preserving shadow gain,
     preserves black, tapers to zero in highlights.
  2. Highlight recovery/rolloff (0 neutral): compress luminance above
     scene-white using a bounded ratio, scale RGB uniformly to preserve hue.
  3. Local contrast/clarity (0 neutral): compare current luminance to
     precomputed shared pyramid log-luminance at a bounded coarse LOD;
     apply limited luminance-only microcontrast with no new texture.
  4. Warm halation (0 neutral): use already shared bright pyramid;
     independent additive warm fringe via the existing bloom source,
     not a physically accurate lens model or new renderer.
  5. Shadow/highlight split tone (two sliders, 0 neutral):
     subtle weighted warm/cool transform by relative luminance; avoid
     black crush by scaling preexisting channels rather than additive lift.
  6. Fine low-amplitude dither (0 neutral): bounded signal-level
     high-frequency noise before vanilla tonemap to reduce gradient
     quantization in this stage. This is NOT a claim of final display-space
     debanding; post-tonemap ordering remains unpromoted.

SAFETY AND COLOR NOTES
  Current per-channel tone shoulder may alter chroma. Implement luminance
  shoulder scaling to preserve color ratios and avoid unnecessary greying.
  Use bounded shadow and highlight transfer functions, never unconditional
  full-screen grey blend. Maintain HDR >1 where appropriate.
  Optional effects default to 0 (OFF); presets remain restrained.
  Treat halation as screen-space/pyramid approximation, not native glow or
  direct control of Skyrim emissive materials.

GRAPH / PACKING RESEARCH — PRIMARY MICROSOFT SOURCES
  https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-packing-rules
    HLSL cbuffer values fill 16-byte four-component registers and must
    not straddle 16-byte boundaries.
  https://learn.microsoft.com/en-us/windows/win32/direct3d11/overviews-direct3d-11-resources-buffers-constant-how-to
    C++ constant-buffer struct must match HLSL declaration layout.
  https://learn.microsoft.com/en-us/windows/desktop/direct3dhlsl/d3dcompile-constants
    D3DCOMPILE_WARNINGS_ARE_ERRORS means HLSL warning is a release blocker.
  Place added scalars in complete groups of four in C++ and HLSL in the
  same order. The existing shader uses PSMain/PSComposite compilation
  at runtime; CI C++ success alone does not prove all HLSL snippets compile,
  so add static source-parity tests and retain fail-closed compile errors.
