======================================================================

independent DATA reviews.

- 11,508 frames / ~6.4 minutes;

- perfect global full-resolution RGBA8 temporal ping-pong;
- perfect 2x2 RGBA16F temporal reduction/adaptation ping-pong;

  authoritative explicit operands.

The engineering goal was therefore sharply bounded.

======================================================================
3. DEFERRED-CONTEXT CARTOGRAPHY
======================================================================

Added:

    include/gzfx/diagnostics/deferred_context_cartography.hpp
    src/diagnostics/deferred_context_cartography.cpp

The module records commands while Skyrim is building D3D11 deferred command
lists.

This is required because ID3D11CommandList exposes no API that enumerates its
recorded commands after FinishCommandList.

The observation path is now:

    ID3D11Device::CreateDeferredContext
    ->
    GZFX attaches a context-local tracker
    ->
    Skyrim records state / Draw / Dispatch / explicit operations
    ->
    FinishCommandList seals a GZFX command-list record
    ->
    Skyrim ExecuteCommandList reaches the primary immediate context
    ->
    GZFX joins the sealed internal run stream to the real gameplay frame.

This closes the principal 0.0.24 late-stack opacity.

======================================================================
4. CREATEDEFERREDCONTEXT HOOK
======================================================================

Renderer Forensics now resolves and globally detours only the required device
method:

    ID3D11Device::CreateDeferredContext

D3D11 device vtable index:

    27

The method address is resolved from the same temporary WARP D3D11 device used
to resolve Present / Resize methods.

The broad old experimental device-vtable interception lane was NOT enabled.

On a successful CreateDeferredContext:

    deferred_context_cartography::AttachContext(...)

is called for the returned deferred context.

Attachment verifies:

    GetType() == D3D11_DEVICE_CONTEXT_DEFERRED

before replacing that context's vtable.

5. DEFERRED CONTEXT STATE IS CONTEXT-LOCAL
======================================================================

Each deferred context owns independent tracked state.

Tracked categories include:

    VS/HS/DS/GS/PS/CS shader identity
    SRVs
    constant buffers
    samplers
    RTVs
    DSV
    OM UAVs
    CS UAVs
    blend state
    depth/stencil state
    raster state
    primitive topology
    viewport
    recording generation
    run ordinal
    recorded compact runs
    overflow state.

This is intentionally separate from the immediate-context Pipeline Cartography
state.

Multiple deferred contexts can therefore be recorded without one worker
thread contaminating another worker context's D3D state.

======================================================================
7. FINISHCOMMANDLIST SEAL
======================================================================

Deferred context vtable index:

    FinishCommandList = 114

On successful FinishCommandList:

GZFX seals an immutable CommandListRecord containing:

    command-list canonical identity
    monotonic command-list generation
    deferred-context identity
    deferred-context generation
    recording generation
    FinishCommandList restore-state flag
    complete/overflow state
    original pass count
    retained compact run stream.

Raw command-list pointer identity is NOT treated as sufficient history.

A reused COM pointer receives a new GZFX generation.

This directly addresses the 0.0.24 observation that command-list pointer
addresses are heavily reused.

======================================================================
8. FINISHCOMMANDLIST STATE SEMANTICS
======================================================================

The tracker mirrors D3D11 restore-state behavior.

FinishCommandList(FALSE):

    tracked deferred state resets to default after the list is sealed.

FinishCommandList(TRUE):

    tracked deferred state is preserved.

A new recording generation begins after every FinishCommandList.

The dedicated CI gate exercises both cases.

======================================================================
9. NESTED DEFERRED COMMAND LISTS
======================================================================

Deferred-context ExecuteCommandList is instrumented.

When a known child list is executed while another deferred list is being
recorded:

    a nested-list marker is recorded;
    known child runs are carried into the parent recording.

Unknown child lists remain explicit opaque nested markers rather than
fabricated data.

Restore-state behavior is mirrored in the tracked deferred state.

The dedicated late-stack CI gate exercises nested list behavior.

======================================================================
10. IMMEDIATE FRAME JOIN
======================================================================

The existing primary immediate-context ExecuteCommandList hook now asks:

    deferred_context_cartography::ExecuteObservedCommandList(...)

for non-GZFX-owned lists.

If a sealed Skyrim list is known:

    its internal run stream is emitted with:
        real gameplay frame
        immediate execute ordinal
        command-list generation
        context generation
        recording generation
        internal recording ordinal range
        repeat count
        pass/resource evidence.

If unknown:

    it remains an opaque Skyrim command-list execution.

The old ownership.csv timeline is retained.

======================================================================
11. BOUNDED DEFERRED EVIDENCE
======================================================================

The deferred recorder is fail-soft.

Maximum retained runs in one recording:

    65,536

Maximum live sealed command-list records:

    256

On run overflow:

    rendering continues
    overflow is marked
    diagnostic counters increment.

On registry pressure:

    oldest generation is evicted
    eviction counter increments.

The renderer is never failed because forensic telemetry exceeded a storage
bound.

======================================================================
12. TRUE EXPLICIT OPERATION LINEAGE
======================================================================

The 0.0.24 compact telemetry problem was repaired.

Explicit D3D operations now carry authoritative operands.

CopyResource:

    explicit read  = source
    explicit write = destination

CopySubresourceRegion:

    source identity
    destination identity
    source subresource
    destination subresource

ResolveSubresource:

    source identity
    destination identity
    source subresource
    destination subresource
    format

ClearRTV:

    explicit write = resource behind RTV

ClearDSV:

    explicit write = resource behind DSV
    clear flags retained

ClearUAV:

    explicit write = resource behind UAV

GenerateMips:

    explicit read/write = resource behind SRV

ExecuteCommandList:

    no fake bound-state resources are treated as list contents.

The same rules are applied inside deferred-context recording.

15. D3D11 RESOURCE HAZARD MIRRORING
======================================================================

During CI hardening, the deferred tracker was corrected to mirror D3D11
resource hazard behavior.

When a resource becomes an output:

    conflicting tracked SRV reads are removed.

This prevents stale deferred binding state from claiming an input resource is
still bound when D3D11 has effectively unbound the conflict.

Commit:

    719d6d6e...
    fix: mirror D3D11 deferred resource hazard unbinding

This is an evidence-correctness repair, not cosmetic test appeasement.

======================================================================
16. HDR REDUCTION STAGE PROMOTION
======================================================================

Semantic Authority now contains a late-stage state machine.

It begins only after:

    AfterAmbientScreenSpaceComposite

and recognizes a coherent descending:

    R16G16B16A16_FLOAT

reduction chain.

Rules include:

    descending dimensions
    previous reduction output consumed by next step
    progression into a tiny target
    final target <= 4x4
    first coherent chain per frame.

When the tiny reduction completes:

    Boundary::HDRReduction
    Phase::AfterExecution
    reason=hdr_reduction_complete

is emitted.

No observed shader pointer is hardcoded.

======================================================================
17. BEFORE TONEMAP PROMOTION
======================================================================

After the HDR reduction chain is complete, the first qualifying full-resolution
R8G8B8A8_UNORM image-space output that consumes the final reduction/adaptation
resource and precedes global TAA triggers:

    Boundary::BeforeTonemap
    Phase::BeforeExecution
    reason=hdr_tonemap_entry

There is still no invented AfterTonemap boundary.

======================================================================
18. GLOBAL TAA PROMOTION
======================================================================

The full-resolution temporal family is detected using resource invariants.

Requirements include:

    late-stage eligible
    tonemap entry already observed
    reads MOTION
    reads MAIN_DEPTH_CURRENT
    reads at least two full-resolution R8G8B8A8_UNORM resources
    writes exactly two full-resolution R8G8B8A8_UNORM outputs
    first qualifying family per frame.

Before execution:

    Boundary::BeforeGlobalTAA
    reason=global_taa_entry

After execution:

    Boundary::AfterGlobalTAA
    reason=global_taa_complete

No field shader address is embedded in the detector.
