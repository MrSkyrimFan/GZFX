======================================================================
5. WHY 0.0.20 EXISTS
======================================================================

0.0.19 successfully proved the concept of a runtime Semantic Authority and
Stage Scheduler, but the real-Skyrim campaign exposed three architectural
mistakes.

A. AfterCameraZ was tied to first semantic promotion.

Result:

CameraZ was rebuilt every frame, but the scheduler did not emit a per-frame
AfterCameraZ event once the resource identity was already known.

B. The late exterior depth resource was assigned the timeless semantic:

OPAQUE_FINAL_DEPTH

Research Pass 2 proved this was wrong.

The same physical resource has multiple content epochs.

Before the per-frame MAIN_DEPTH copy it is consumed by Skyrim's exterior
volumetric temporal pass as:

VOLUMETRIC_PREVIOUS_DEPTH

After MAIN_DEPTH is copied into the same physical texture it becomes:

PRE_WATER_DEPTH_CURRENT

C. Persistent identity was too easy to confuse with current semantic
availability.

Exterior volumetric resources could remain known in the registry after
entering an interior even though they were not valid current-frame inputs.

0.0.20 corrects all three.

7. PERSISTENT RESOURCE IDENTITY
======================================================================

The authority retains persistent structural information for known resources.

ResourceInfo tracks:

- semantic family
- confidence
- canonical IUnknown identity
- generation
- first seen frame
- last seen frame
- D3D resource dimension
- width
- height
- depth
- mip count
- array size
- DXGI format
- bind flags

Persistent identity is useful for:

- structural reacquisition
- diagnostics
- continuity
- recognizing a resource across frames

Persistent identity does NOT imply that a production effect may consume that
resource in the current frame.

8. CURRENT-FRAME AVAILABILITY
======================================================================

0.0.20 adds AvailabilityInfo.

It tracks:

- observedThisFrame
- producedThisFrame
- consumedThisFrame
- currentFrameAvailable
- previousFrameAvailable
- frame
- lastObservedFrame
- lastProducedFrame
- lastConsumedFrame
- contentEpoch
- epochKind
- environmentScope
- validFromStage
- validUntilStage

At frame transition:

current availability is reset

while:

persistent resource identity is retained.

This directly fixes the stale exterior-resource problem found in 0.0.19.

======================================================================
9. QUERY MODES
======================================================================

The authority now defines explicit semantic query intent.

Query modes:

CurrentFrame
PreviousFrameHistory
PersistentIdentity
DiagnosticAnyKnown

The new public query contract is stage-aware:

QuerySemantic(
    semantic,
    mode,
    frame,
    atStage,
    outView
)

CurrentFrame lookups fail closed unless:

- physical identity exists
- the semantic is valid for the requested frame
- currentFrameAvailable is true
- the requested stage lies inside the validity window
- environment scope is compatible when environment is known

PreviousFrameHistory uses a separate availability contract.

This prevents a stale resource from being accidentally treated as a current
rendering input merely because its pointer still exists in the session
registry.

RESOURCE IDENTITY != RESOURCE CONTENT MEANING.

17. AFTER_OPAQUE_WORLD_MRT
======================================================================

New structural boundary:

AfterOpaqueWorldMRT

Purpose:

identify the transition from the known four-target opaque world MRT into the
stock CameraZ producer.

The authority does not use a fixed draw ordinal.

The state machine requires:

- main four-target MRT has been observed this frame
- first recognized CameraZ producer begins
- AfterOpaqueWorldMRT has not already fired this frame

Then it signals the boundary once.

This is the future candidate boundary for building a GZFX-owned post-opaque
depth hierarchy in Wave 3.

0.0.20 does not build that hierarchy yet.

======================================================================
18. AFTER_CAMERAZ — FIXED PER FRAME
======================================================================

0.0.19 failure:

CameraZ identity was discovered correctly, but AfterCameraZ was tied to
semantic promotion.

Once the resource identity was known, later frames had no promotion and no
stage event.

0.0.20 separates:

resource discovery

from:

hierarchy completion this frame.

The authority now tracks:

- current CameraZ candidate identity
- current frame mip-write mask
- required mip count derived from descriptor
- whether completion has already been signaled this frame

When required mip coverage is complete:

STOCK_CAMERAZ is marked current for the frame

and:

AfterCameraZ

fires exactly once for that applicable frame.

This works independently of whether the resource was first discovered that
frame or hundreds of frames earlier.

26. D3D11 STATE / HAZARD BEHAVIOR
======================================================================

The 0.0.19 D3D11 read/output hazard mirroring remains intact.

When a resource becomes an output, stale matching SRV state is removed from
the semantic observer.

When an SRV conflicts with a current output, the authority does not report it
as a live read.

This prevents false producer/consumer edges caused by D3D11's automatic
hazard unbinding behavior.
