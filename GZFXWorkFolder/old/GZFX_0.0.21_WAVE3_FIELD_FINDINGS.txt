1. EXECUTIVE VERDICT
======================================================================

The test run is valid and useful.

The user successfully produced all twelve requested Wave 3 capture folders
despite the original capture instructions requiring awkward simultaneous

The run proves that the new Wave 3 production path is executing in real
Skyrim, at the intended renderer stage, across exterior/interior/exterior
domains, without crashing or corrupting the already-closed foundation.

However:

THE TEMPORAL CORE DOES NOT REUSE HISTORY.

The primary root cause is now directly evidenced.

NORMAL_MASK_CURRENT is a field-known physical ping-pong semantic. Its physical
resource identity changes as part of normal Skyrim operation.

The 0.0.21 temporal reset logic compares the native-normal semantic generation
against the prior frame and treats any generation change as a temporal
continuity break.

Because the normal semantic ping-pongs, this condition fires continuously.

Result:

- every Wave 3 execution resets temporal history;
- history generation increments every execution;
- history confidence never accumulates;
- history accepted mask remains zero;
- the rejection/debug mask reports invalid history across the full frame;
- history_reused_candidate remains false.

This is not a user-test failure.

This is an implementation lifecycle defect.

The field run also exposes a second diagnostic defect:

The CameraZ comparison code currently treats any positive STOCK_CAMERAZ value
as geometry.

Field images prove STOCK_CAMERAZ represents background/sky with positive depth
values, so stock-only geometry counts are contaminated by background.

Therefore the current:

    gzfx_only_geometry
    stock_only_geometry
    both_background

classification cannot yet be used to prove post-opaque geometry coverage.

The underlying GZFX hierarchy itself visually appears coherent and closely
matches stock CameraZ over common geometry.

8. DIRECT ROOT-CAUSE PROOF
======================================================================

The root cause is not inferred only from output masks.

It is corroborated by the current source and the semantic-authority evidence.

Current Wave 3 history reset code compares:

    inputs.mainDepth.semanticGeneration
    inputs.motion.semanticGeneration
    inputs.nativeNormal.semanticGeneration

against the prior frame.

If any differ:

    ResetReason::SemanticGenerationChanged

Current Semantic Authority generation changes when the physical semantic
identity changes.

The native normal is already known to ping-pong physical resources.

The field evidence records the following consecutive frames inside one
three-frame capture:

Frame 4733:
    NORMAL_MASK_CURRENT
    identity 0x1AAFA5D2060
    generation 5646

Frame 4734:
    NORMAL_MASK_CURRENT
    identity 0x1AAFA5CFE30
    generation 5649

Frame 4735:
    NORMAL_MASK_CURRENT
    identity 0x1AAFA5D2060
    generation 5652

This is normal ping-pong behavior.

It is not a renderer discontinuity.

Therefore:

PHYSICAL RESOURCE GENERATION IS CURRENTLY BEING USED AS A LOGICAL SEMANTIC
CONTINUITY TOKEN.

That is incorrect for ping-pong semantic families.

The repair must distinguish:

    logical semantic-family continuity

from:

    current physical backing-resource identity / generation

A valid current NORMAL_MASK_CURRENT backing texture may change every frame
without invalidating temporal history.

10. CAMERAZ COMPARISON DIAGNOSTIC DEFECT
======================================================================

The current comparison classifies:

    stockValid =
        isfinite(STOCK_CAMERAZ) && STOCK_CAMERAZ > 0

This assumption is wrong for the observed stock hierarchy.

Across every capture:

    both_background=0

That means stock CameraZ is considered positive/valid over the entire frame,
including visible sky/background regions.

The visual stock-only masks confirm the problem.

For example, exterior captures mark broad sky/background regions as
"stock-only geometry."

Therefore these counts:

    gzfx_only_geometry=0
    stock_only_geometry=...
    both_background=0

do NOT currently prove that stock CameraZ contains more geometry than
GZFXSceneDepthHierarchy.

They prove that the comparison's stock-background predicate is wrong.

The GZFX hierarchy intentionally writes:

    background = 0

while stock CameraZ uses a different positive background/far representation.

Required research/repair:

- identify the stock CameraZ background/far sentinel/representation;
- compare common geometry using a valid stock-background test;
- or compare against the native source depth / early-copy mask to distinguish
  actual geometry from CameraZ background;
- do not use positive-vs-zero as the geometry classifier.

FIELD VERDICT:

CAMERAZ NUMERICAL COMMON-PIXEL COMPARISON = USEFUL
CAMERAZ GEOMETRY CLASSIFICATION = FAIL / MUST BE FIXED

12. HUMAN TEST ERGONOMICS - NEW PERMANENT RULE
======================================================================

The user is one human with two hands.

Future GZFX field instructions MUST NOT require simultaneous combinations such
as:

    move
    + strafe
    + turn camera
    + hold Shift
    + press Numpad5

as the only valid way to capture evidence.

Preferred designs:

A. ARM-THEN-ACT

    press Shift+Numpad5
    ->
    GZFX arms a 2-3 second diagnostic window
    ->
    user performs the requested movement naturally

or:

B. BUFFERED CAPTURE

    GZFX continuously retains a tiny bounded recent diagnostic ring
    ->
    Shift+Numpad5 saves the preceding/following short window

or:

C. AUTOMATED MOVEMENT WINDOW CLASSIFICATION

    capture request arms the system
    ->
    GZFX detects stationary / slow / fast motion frames internally

User-facing instructions should require at most normal gameplay controls plus
one simple capture action, not octopus choreography.
