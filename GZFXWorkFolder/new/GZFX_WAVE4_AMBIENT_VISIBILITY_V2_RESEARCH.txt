1. EXECUTIVE DECISION
======================================================================

Wave 4 should build the first production graphics-quality effect on top of the
now field-closed renderer foundation.

Feature:

    AMBIENT VISIBILITY v2

Algorithm family:

    clean-room GTAO-inspired horizon visibility

Integration:

    replace Skyrim's final filtered SAO visibility surface
    AFTER stock AO completes
    BEFORE Skyrim's Ambient Screen-Space Composite consumes it

This is the critical architectural decision.

Do NOT:

    multiply HDR scene color late
    reuse the failed old half-resolution Horizon/HBAO prototype
    reconstruct normals from depth as the primary surface orientation
    create another duplicate depth hierarchy
    create another independent temporal system

Wave 4 should consume the systems Wave 3 proved:

    GZFXSceneDepthHierarchy
    native NORMAL_MASK_CURRENT
    native MOTION
    camera data
    GZFX temporal geometry confidence/reprojection validity
    Stage Scheduler
    Renderer Execution Service

The first production effect should finally operate as a renderer component,
not as a post-processing trick.

======================================================================
2. WHY GTAO IS THE RIGHT ALGORITHM FAMILY
======================================================================

The old GZFX Horizon/HBAO-style experiments failed in the field because they
combined several weak assumptions:

- fixed screen-space sampling;
- poor surface orientation before native normals were known;
- half-resolution analysis;
- no reliable temporal geometry foundation;
- overly global response;
- late scene-color multiplication;
- large visible horizontal/crawling patterns.

GTAO addresses the important algorithmic side of this failure.

The Activision work derives an ambient visibility approximation from horizon
angles in projected slices rather than merely summing arbitrary depth
differences.

Important properties:

- world-space radius;
- directional horizon search;
- surface-normal-aware visibility integration;
- bounded falloff;
- physically/radiometrically motivated visibility term;
- low sample counts with temporal/spatial filtering;
- natural separation between scalar visibility and later indirect/multiple
  bounce lighting.

XeGTAO demonstrates a practical modern implementation and confirms:

- full-resolution rendering is a strong quality baseline;
- hierarchical view-space depth is valuable for cache-efficient larger radii;
- 32-bit view-space depth materially improves quality;
- a small number of slices/steps is sufficient;
- depth-aware denoise is important;
- temporal noise is expected to be filtered rather than hidden by huge sample
  counts.

This maps unusually well onto the exact systems GZFX just finished.

======================================================================
3. FULL RESOLUTION IS THE WAVE 4 BASELINE
======================================================================

Wave 4 should begin at full active render resolution.

Reference field resolution:

    2560x1440

Reasons:

1. The old GZFX half-resolution Horizon path flickered/crawled badly.

2. NVIDIA's HBAO+ material explicitly identifies full-resolution operation as
   an important improvement over older half-resolution AO behavior.

3. XeGTAO's modern default/high quality paths are designed to work at full
   resolution.

4. Wave 3 GPU infrastructure is currently inexpensive enough that there is no
   evidence forcing a half-resolution compromise.

5. The user is targeting ENB-class or better visual quality, not lowest-common-
   denominator post-processing.

Do not optimize to half resolution before measuring the real production pass.

======================================================================
4. USE THE GZFX R32 HIERARCHY DIRECTLY
======================================================================

Wave 4 must NOT construct another depth pyramid.

The field-proven:

    GZFXSceneDepthHierarchy

already provides:

    R32_FLOAT
    positive view-space depth
    post-opaque coverage
    full mip chain to 1x1
    full-resolution mip0
    weighted/far-aware reduction

Wave 3 real-game evidence proved:

- correct scale/sign against CameraZ on common geometry;
- additional post-opaque geometry missed by stock CameraZ;
- stable construction at the exact renderer stage needed by Wave 4.

GTAO's sample radius naturally benefits from choosing coarser hierarchy mips
for farther screen-space offsets.

Recommended mip selection concept:

    samplePixelDistance = length(offsetPixels)

    mip =
        clamp(
            log2(samplePixelDistance) - depthMipBias,
            0,
            mipCount - 1)

Use point sampling within a chosen mip to avoid blending unrelated depth
surfaces across discontinuities.

No D3D11 GenerateMips.

======================================================================
5. NATIVE NORMALS
======================================================================

Primary normal:

    NORMAL_MASK_CURRENT.RG

Use the already field-proven native Skyrim decode.

Do not use depth-derived normals as a silent fallback.

Wave 4 should fail soft to stock AO for a frame when the required native
normal semantic is unavailable.

That is preferable to reintroducing the exact unstable approximation the

======================================================================
6. CLEAN-ROOM GTAO MAIN PASS
======================================================================

Implement independently from the public paper and MIT XeGTAO concepts.

Do not copy GPL Community Shaders shader code.

Core per-pixel sequence:

1. read current positive view-space depth from hierarchy mip0;

2. background:
       visibility = 1
       return;

3. decode native view-space normal;

4. reconstruct current view-space position;

5. compute view vector toward the camera;

6. compute a world-space effect radius projected to a screen-space radius at
   the current depth;

7. rotate a small set of horizon slices using deterministic per-pixel/frame
   low-discrepancy noise;

8. for each slice:
       sample both directions;
       distribute steps non-linearly from near to far;
       choose hierarchy mip from sample distance;
       reconstruct sampled view position;
       calculate sample horizon vector;
       apply world-radius/falloff rejection;
       retain the strongest valid horizon on each side;

9. integrate the two horizons against the projected surface normal;

10. average visibility across slices;

11. apply a mild user/engineering power curve only after the physical
    visibility term is formed;

12. output:
       visibility in [0,1]
       1 = unoccluded
       0 = fully occluded

Wave 4 should not emit bent normals yet.

Bent normals are valuable, but they add cost and are more important once GZFX
has environment/indirect radiance that can consume them.

======================================================================
8. INITIAL WORLD-SPACE PARAMETERS
======================================================================

These are engineering seeds, not final artistic truth.

Suggested starting values:

    effect radius:
        ~240 Skyrim world units

    falloff range:
        last ~35% of radius

    sample distribution power:
        ~2.0

    thin-occluder compensation:
        conservative / near zero initially

    visibility power:
        1.0

    minimum practical screen radius:
        roughly 1-2 pixels

The radius must be WORLD-SPACE driven.

Do not return to an arbitrary "96 screen pixels everywhere" artistic control.

A world-space radius naturally shrinks on distant surfaces and avoids the
global-gray behavior seen in the old prototype.

======================================================================
9. SPATIAL FILTER
======================================================================

The raw signal will be noisy at practical sample counts.

Use a small depth/normal-aware spatial filter.

Recommended baseline:

    separable bilateral
    horizontal pass
    vertical pass

Each pass:

    5 taps

Weight by:

    Gaussian-ish spatial distance
    relative view-depth difference
    native-normal agreement

This is simple, predictable, full resolution, and avoids a huge kernel.

Alternative 5x5 single compute pass is viable, but separable filtering is
easier to time/debug independently.

Do not blur across depth silhouettes.

Do not allow sky/background to bleed into geometry.

======================================================================
10. TEMPORAL INTEGRATION
======================================================================

Wave 4 should NOT create another geometry-history system.

Wave 3 already owns:

    previous linear depth
    previous world normal
    geometry confidence
    native-motion reprojection validation
    disocclusion masks

Wave 4 needs only signal history:

    PreviousAmbientVisibility

Use:

    previousUV =
        currentUV + nativeMotion.xy

but accept prior AO only when Wave 3 says the current pixel's previous geometry
was valid.

Recommended signal reuse inputs from Wave 3:

    current geometry confidence
    current reprojection accepted mask

Wave 4 then:

1. samples previous AO at previous dynamic-resolution mapping;

2. rejects if Wave 3 reprojection is invalid;

3. calculates current spatial AO neighborhood min/max;

4. clamps reprojected AO into that current neighborhood range;

5. blends according to Wave 3 confidence and current motion;

6. writes current AO history.

This avoids duplicating depth/world/normal disocclusion math.

The Wave 4 temporal system is therefore:

    signal history

not:

    geometry history v2.

11. WAVE 3 MUST EXPOSE A PRODUCTION FRAME VIEW
======================================================================

Add a narrow read-only Wave 3 API.

Suggested:

    struct FrameView
    {
        uint64_t frame;
        uint64_t historyGeneration;

        UINT width;
        UINT height;
        UINT mipCount;

        ID3D11ShaderResourceView* depthHierarchy;
        ID3D11ShaderResourceView* geometryConfidence;
        ID3D11ShaderResourceView* reprojectionMask;

        bool historyValid;
        bool valid;
    };

API:

    bool AcquireFrameView(
        uint64_t frame,
        FrameView* outView) noexcept;

    void ReleaseFrameView(
        FrameView& view) noexcept;

Returned SRVs are AddRef'd.

The view is valid only for the current produced frame.

This lets future renderer features reuse the Wave 3 foundation without
reaching into private Wave 3 globals.

Wave 4 is the first consumer.

======================================================================
12. COMPUTE STAGE
======================================================================

Wave 4 visibility computation should run from:

    AfterOpaqueWorldMRT

Registration order:

    Wave 3 initializes/registers first
    Wave 4 initializes/registers second

The Stage Scheduler invokes callbacks in registration order.

Therefore:

    AfterOpaqueWorldMRT
    ->
    Wave 3 builds hierarchy and temporal geometry
    ->
    Wave 4 consumes the completed current Wave 3 frame view

Wave 4 then records one GZFX-owned deferred command list containing:

    raw GTAO
    spatial horizontal
    spatial vertical
    temporal accumulation

No MAIN_HDR modification occurs here.

The final visibility remains in GZFX-owned R16_FLOAT resources.

======================================================================
13. WHY R16_FLOAT IS SUFFICIENT FOR THE AO SIGNAL
======================================================================

Depth remains R32_FLOAT.

The scalar ambient visibility output is bounded:

    [0,1]

R16_FLOAT is more than sufficient precision for:

    raw visibility
    filtered visibility
    temporal AO history

Using R32_FLOAT for the visibility term would double bandwidth without a
meaningful visual benefit.

This does NOT weaken the R32 depth architecture.

======================================================================
14. THE STOCK SKYRIM INTEGRATION BREAKTHROUGH
======================================================================

The field-closed renderer map provides a much better integration point than
the old pre-UI HDR mutation.

The stock AO family is:

    temporal RawAO
    ->
    filter temp
    ->
    final SAO_FILTERED

Final SAO_FILTERED is:

    full resolution
    R8G8B8A8_UNORM
    RTV + SRV + UAV capable

The stock Ambient Screen-Space Composite later consumes:

    RAW_INDIRECT
    SAO_FILTERED
    depth
    normal
    auxiliary inputs
    other lighting resources

and writes:

    MAIN_HDR

Crucially:

the RAW_INDIRECT pass between stock AO and the ambient composite does NOT
consume SAO_FILTERED.

This creates a clean interval:

    stock final AO complete
    ->
    AfterStockAO
    ->
    raw indirect pass
    ->
    BeforeAmbientScreenSpaceComposite
    ->
    ambient composite consumes AO

Wave 4 can replace SAO_FILTERED immediately after stock AO without disturbing
raw indirect generation.

Skyrim then performs its own normal ambient-light composition using GZFX's
visibility term.

This is the preferred production integration.

15. SAO_FILTERED REPLACEMENT
======================================================================

At:

    AfterStockAO

Wave 4 should:

1. query Semantic Authority for:
       SAO_FILTERED
       CurrentFrame
       AfterStockAO

2. acquire the actual currently bound stock AO output texture;

3. validate:
       2560x1440/current resource size
       R8G8B8A8_UNORM

       GZFXStockAOCopy

       unbinds render targets
       binds SAO_FILTERED as UAV
       reads final GZFX R16 visibility
       writes float4(v,v,v,1)

6. execute with:
       ExecuteCommandList(..., TRUE)

7. restore Skyrim immediate-context state automatically.

The physical stock AO texture remains the resource Skyrim already expects.

Only its content changes.

======================================================================
16. FAIL-SOFT STOCK FALLBACK
======================================================================

Wave 4 must preserve Skyrim stock AO automatically whenever GZFX is not
confident.

If any required condition fails:

    Wave 3 frame view missing
    native normal unavailable
    motion unavailable for temporal mode
    camera unavailable
    GZFX runtime creation failure
    SAO_FILTERED unavailable
    wrong stock AO format
    execution failure

then:

    DO NOT MODIFY SAO_FILTERED

Skyrim's stock AO remains intact and its stock ambient composite proceeds.

This is the correct failure mode.

No black frame.

No unoccluded frame.

No guessed fallback normal.

======================================================================
24. NIGHT / INTERIOR / EXTERIOR EXPECTATIONS
======================================================================

Ambient visibility is geometric.

The scalar visibility term should be stable across:

    daylight exterior
    night exterior
    interior

The lighting impact can differ because Skyrim's ambient-light composition
differs.

This is another advantage of injecting the visibility term into the stock
ambient composite rather than directly multiplying final HDR.

GZFX computes geometry visibility.

Skyrim's ambient lighting determines how that visibility affects the lit
scene.

That separation is exactly what a renderer-native implementation should do.
