13. HDR TERMINAL / BEFORETONEMAP BUG
======================================================================

BeforeTonemap count:

    0

The reason is now concrete.

Current HDR completion rule:

    step >= 4
    width <= 4
    height <= 4

The chain reaches:

    3x2

and the detector immediately sets:

    hdrReductionComplete = true
    hdrReductionFinalIdentity = 3x2 resource

The real chain then performs:

    3x2 -> 2x2

But ObserveHdrReductionLocked returns once hdrReductionComplete is true, so the
final identity is never updated to the 2x2 resource.

The full-resolution current-image / tonemap candidate later reads:

    final 2x2 reduction/adaptation resource

NOT:

    stored 3x2 detector identity.

Therefore the current BeforeTonemap rule:

    reads hdrReductionFinalIdentity
    AND writes full-resolution RGBA8

never matches.

DATA classification:

    BeforeTonemap zero count = PROVEN DETECTOR TERMINAL BUG

Required design correction:

    identify the true terminal 2x2 node / downstream exposure resource before
    committing HDRReduction terminal identity.

Do not treat 3x2 as final merely because it satisfies <=4x4.

16. RESOURCE CREATION PROVENANCE — IMPORTANT LIMIT
======================================================================

Creation-time hooks clearly operated, but several core long-lived Skyrim render
targets still appear in the registry as:

    unknown/preexisting

including important semantic families such as:

    MAIN_HDR
    MAIN_DEPTH
    MOTION
    NORMAL / related long-lived surfaces.

Late image-space shader identities, by contrast, have strong SkyrimSE.exe
creator provenance.

This does NOT mean the creation hooks failed.

It indicates some core renderer resources existed before the 0.0.26 identity
observer first encountered them.

Source review of the bootstrap is required in RESEARCH before deciding why.

One important current source fact:

    dinput8.dll DllMain does not load GZFX.dll.

Instead:

    Skyrim calls a dinput8 export
    -> Prepare()
    -> EnsureGzfx()
    -> LoadLibraryW(GZFX.dll)
    -> GZFX_Initialize()

Therefore GZFX initialization timing depends on when Skyrim first uses DirectInput.

It is plausible that some D3D renderer/device/resource initialization occurs
before that first DirectInput export.

This must be researched carefully.

Do NOT simply move heavy initialization into DllMain because Windows loader-lock
constraints make that unsafe.
