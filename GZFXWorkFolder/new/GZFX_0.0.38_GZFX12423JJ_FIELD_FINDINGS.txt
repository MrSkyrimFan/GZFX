CODE-AUDIT DEFECTS / VERIFIED ENGINEERING OPPORTUNITIES
  src/settings.cpp kDescriptors:
    many cinematic controls expose destructive ranges:
      indirect <=0.60, glow <=1.5, HBAO <=2.0, bloom <=3.0,
      exposure EV +/-4, contrast <=2, saturation <=2,
      vignette <=1, DoF radius <=32, fog density <=4,
      sharpening <=2, CA <=8.
    broad linear sliders map full user drag to those ranges.
    existing persistent values read via descriptor clamp and NormalizeRelations;
    changing descriptors can safely cap older settings on reload without
    requiring manual INI deletion.

  src/settings.cpp SetNormalized(ProductPreset):
    writes the enum/label and persists but never calls ApplyPresetUnlocked.
    ApplyPresetAction is separate. UI suggests a selected look has applied when
    underlying live fields can remain from the previous look. This is a genuine
    control/preset UX defect and can masquerade as nonfunctional sliders.
  src/settings.cpp ApplyPresetUnlocked:
    begins from g_values (current edited state) then resets only selected
    families. Existing ambient HBAO/indirect/LocalGlow carry over untouched.
    Therefore switching a built-in look does not provide a clean known baseline.
  No explicit factory/reset action is defined in settings::Editable/Activate.
  Custom slot persistence exists; it must not be destroyed by reset.

  src/render/runtime_state.cpp:
    modes 0/1/2/3/4, CycleDevelopmentMode=(current+1)%5.
    1=debug split ambient; 2=full ambient; 3=depth; 4=pre-UI color.
    owner requirement is strictly 0=vanilla, 2=GZFX ON on hotkey.
    Existing debug captures can remain internal but not user mode choices.
  src/render/visible_pass.cpp and src/render/ambient_visibility_v2.cpp:
    debug split semantics are controlled by development mode; normal GZFX is
    mode 2. Retain fail-closed off path and menu draw ability.
  src/ui/settings_menu.cpp:
    Shift+Numpad3 requests mode cycle, rendering relies on settings::GetNormalized.
    Every slider drag persists INI and bumps settings revision; both value mapping
    and actual render kernel must be tuned, not only menu labels.

  src/render/unified_product_renderer.cpp:
    one MAIN_HDR source snapshot, shared bloom/exposure pyramid,
    one ordered composite, one writeback. Valid integration point for additional
    post/tone controls WITHOUT adding independent renderers.
    Color operations apply raw lift/gain/pow/saturation/contrast; tone shoulder
    compresses all channels; original shader allows extreme destructive ranges.
    Existing exposure history is not automatically reset on every look edit.
    Current effect mask names cover existing post, HBAO, indirect and LocalGlow.
    New features must have real parameters, actual HLSL response, mask/status
    visibility, persistence, and regression tests; do not label TODOs features.
