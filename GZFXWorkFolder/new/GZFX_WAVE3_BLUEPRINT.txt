======================================================================

Where earlier Wave 3 notes differ from the completed Deep Research Pass 3,
the latest research controls.

The following decisions are explicitly superseded/clarified:

Earlier direction:
    approximately five useful mips minimum

Final Wave 3 decision:
    ALLOCATE A FULL MIP CHAIN TO 1x1.

    plain linear / average reduction as the likely first production filter

    default production candidate =
    XeGTAO-style weighted / far-aware reduction

    diagnostic reference =
    linear average

    optional engineering diagnostics =
    minimum and maximum

the Wave 3 diagnostics; the architecture is not blocked on those constants.

    a packed R16G16B16A16_FLOAT representation was considered attractive

        R32_FLOAT

        R8_UNORM

======================================================================
5. LOCKED MOTION CONVENTION
======================================================================

Native Skyrim motion is:

    R16G16_FLOAT

Coordinate space:

    normalized screen UV displacement

Meaning:

    previous - current

Required Wave 3 reprojection:

    previousUV = currentUV + nativeMotion.xy

DO NOT:

    negate motion
    subtract motion
    flip Y again
    convert motion to pixels before history sampling
    inject TAA jitter into the motion vector
    remove jitter from the motion vector

Native motion is generated from unjittered camera transforms.

Pixel-space motion exists only as a diagnostic quantity:

    motionPixels =
        nativeMotionUV * activeRenderSize

======================================================================
6. LOCKED DYNAMIC-RESOLUTION MODEL
======================================================================

The native 720-byte camera buffer contains:

DynamicResolutionParams1:

    x = current width ratio
    y = current height ratio
    z = previous width ratio
    w = previous height ratio

DynamicResolutionParams2:

    x/y = inverse current ratios
    z/w = current / previous clamp-related values

Logical current UV and previous UV MUST use different mappings.

Current:

    currentDRUV =
        currentRatio * currentUV

Previous:

    previousDRUV =
        previousRatio * previousUV

Required temporal flow:

    currentUV
    ->
    currentDRUV
    ->
    sample current motion
    ->
    previousUV = currentUV + motion
    ->
    logical [0,1] bounds test
    ->
    previousDRUV
    ->
    sample previous history

Never map previous history with the current ratio.

History allocations should remain at the full resource/display dimensions.

Ordinary native dynamic-resolution ratio changes should NOT cause texture
reallocation.

Actual resource-size changes DO invalidate/recreate history.

8. RENDERER EXECUTION SERVICE
======================================================================

Current primary device/context ownership lives inside renderer diagnostics.

Production renderer modules must not depend on diagnostic globals.

Wave 3 therefore adds:

    RendererExecutionService

Responsibilities:

    - retain the primary ID3D11Device
    - retain the primary immediate ID3D11DeviceContext
    - retain the primary swap chain when useful
    - expose a renderer/device generation
    - expose a surface generation
    - invalidate cleanly on resize/device replacement
    - provide short-lived AddRef'd execution leases
    - register GZFX-owned command lists / pass tags
    - remain independent of feature-specific rendering logic

Recommended public contract:

    namespace gzfx::render::execution
    {
        enum class OwnedPass : uint32_t
        {
            Unknown = 0,
            Wave3DepthHierarchy,
            Wave3TemporalGeometry,
            Wave3Diagnostics,
            Count
        };

        struct ExecutionLease
        {
            ID3D11Device* device = nullptr;
            ID3D11DeviceContext* immediate = nullptr;
            IDXGISwapChain* swapChain = nullptr;

            uint64_t deviceGeneration = 0;
            uint64_t surfaceGeneration = 0;

            bool valid = false;
        };

        bool AttachPrimary(
            IDXGISwapChain* swapChain,
            ID3D11Device* device,
            ID3D11DeviceContext* immediate) noexcept;

        bool Acquire(
            ExecutionLease* outLease) noexcept;

        void Release(
            ExecutionLease& lease) noexcept;

        void NotifyResizeBegin() noexcept;

        void NotifyResizeComplete(
            bool succeeded,
            UINT width,
            UINT height) noexcept;

        uint64_t DeviceGeneration() noexcept;
        uint64_t SurfaceGeneration() noexcept;

        void TagCommandList(
            ID3D11CommandList* list,
            OwnedPass pass,
            uint64_t frame) noexcept;

        bool QueryOwnedCommandList(
            ID3D11CommandList* list,
            OwnedPass* outPass,
            uint64_t* outFrame) noexcept;

        void RetireCommandList(
            ID3D11CommandList* list) noexcept;
    }

Exact function spelling can be adjusted to repository style.

Required behavior:

- AttachPrimary is called from the already-proven primary swap/device acquisition
  path.
- The service retains its own strong references.
- A real device replacement increments deviceGeneration.
- A successful resize increments surfaceGeneration.
- Production modules acquire a lease rather than reaching into
  renderer_forensics globals.
- Leases are bounded and explicitly released.

11. SEMANTIC AUTHORITY PRODUCTION EXTENSION
======================================================================

The 0.0.20 Semantic Authority remains the canonical semantic classifier.

Do NOT replace it with resource_intelligence.

Wave 3 extends production ownership around it.

Current authority records identity, descriptor, generation and availability.

Wave 3 additionally needs a safe way to obtain the real D3D11 resource that
corresponds to an accepted semantic generation.

Required rule:

    QuerySemantic decides whether a semantic is valid.

Only after QuerySemantic succeeds may production code obtain the resource.

Recommended internal change:

- bound view state retains an ID3D11Resource strong reference while the binding
  is active;
- each accepted semantic record retains one strong resource reference for its
  CURRENT semantic generation;
- replacing a semantic generation releases the old reference;
- resize/device reset releases all semantic strong references.

This is bounded by the semantic enum count.

It is NOT an unbounded global COM-object cache.

Recommended narrow authority API:

    bool AcquireResourceObject(
        Semantic semantic,
        uint64_t expectedGeneration,
        ID3D11Resource** outResource) noexcept;

Contract:

- expectedGeneration must equal the authority's current semantic generation;
- returned resource is AddRef'd for the caller;
- failure returns nullptr;
- this API does NOT bypass availability, stage or environment checks;
- callers must first obtain a successful SemanticView from QuerySemantic.

The public SemanticView remains lightweight metadata.

Production COM lifetime ownership is explicit.

13. CAMERA BUFFER ACQUISITION
======================================================================

The old resource_intelligence path identifies the likely camera buffer using:

    byte width == 720
    VS slot 12
    PS slot 12

That was good enough for diagnostics.

Wave 3 must make the camera signal production-grade.

Recommended acquisition architecture:

A. OBSERVE BINDING

The primary-context constant-buffer hooks already see VS/PS b12.

A candidate becomes production-eligible only when:

    ByteWidth == 720
    AND
    observed at VS slot 12
    AND
    observed at PS slot 12

B. RETAIN THE SELECTED BUFFER

Retain one AddRef'd selected camera ID3D11Buffer for the accepted generation.

C. CAPTURE THE CPU-WRITTEN CONTENT WITHOUT A PER-FRAME GPU READBACK

The existing immediate-context hook layer already observes:

    Map
    Unmap
    UpdateSubresource

The Wave 3 camera provider should capture the 720 bytes from CPU-visible writes
when possible:

- on a successful mapped update, retain the relevant mapped bytes before Unmap;
- on UpdateSubresource, copy the supplied 720-byte source payload;
- associate the captured payload with the candidate buffer and current frame.

This is the normal production path.

D. DO NOT MAKE PER-FRAME STAGING READBACK THE DEFAULT

Existing staging CopyResource + Map validation may remain as:

    diagnostic cross-check
    one-time verification
    CI/test support

It must not become a normal full-frame GPU synchronization point.

E. FAIL CLOSED

If current camera bytes cannot be proven for the frame:

    temporal reuse is invalid
    hierarchy work requiring camera reconstruction is skipped
    bounded diagnostic reason is recorded

Do not silently use arbitrary stale camera bytes.

======================================================================
23. DEPTH REPRESENTATION / BACKGROUND SENTINEL
======================================================================

The hierarchy stores:

    positive view-space depth

Background / invalid depth should use:

    0.0

Rules:

    valid geometry:
        viewDepth > 0

    background:
        viewDepth == 0

Reduction filters must ignore invalid zero samples.

If all source samples are invalid:

    destination = 0

This avoids contaminating depth reductions with an arbitrary far-plane
numeric sentinel.

======================================================================
24. SHARED DEPTH RECONSTRUCTION
======================================================================

Wave 3 MUST have one canonical depth reconstruction implementation.

It is shared by:

    hierarchy generation
    hierarchy debug visualization
    temporal world-position reconstruction
    stock CameraZ comparison diagnostics

Source data:

    native raw device depth
    CameraProjInverse or equivalent validated camera projection data

Canonical conceptual reconstruction:

    clip.x = uv.x * 2 - 1
    clip.y = (1 - uv.y) * 2 - 1
    clip.z = rawDepth
    clip.w = 1

    viewH = mul(CameraProjInverse, clip)
    view = viewH.xyz / viewH.w

    positiveViewDepth = canonical positive forward distance

The implementation must explicitly validate the renderer's forward-Z sign.

DO NOT silently apply abs(view.z) to make bad math look plausible.

One diagnostic comparison against stock CameraZ must prove scale/sign on common
geometry.

After proof, the shared function becomes the only production depth
linearization path.

25. HIERARCHY COMPUTE PIPELINE
======================================================================

Do NOT use D3D11 GenerateMips.

Wave 3 needs controlled geometry reduction.

Preferred compute design:

    BuildDepthHierarchyCS

Thread group:

    8x8 baseline

PASS A:

    read raw MAIN_DEPTH_CURRENT
    reconstruct positive view-space depth
    write mip 0
    use group-shared memory
    reduce mip 1
    reduce mip 2
    reduce mip 3
    reduce mip 4

PASS B / TAIL:

    reduce mip 4 -> mip 5
    mip 5 -> mip 6
    ...
    until 1x1

The tail may use one small dispatch per mip initially.

Correctness beats a clever giant shader.

The tail contains little work and can be optimized later only if profiling
proves it matters.

26. DEFAULT DEPTH REDUCTION
======================================================================

Production candidate:

    WeightedFar

Intent:

    preserve a stable representative depth across slopes and discontinuities
    without inheriting the worst behavior of pure minimum selection.

The implementation should follow the XeGTAO-derived weighted/far-aware
reduction concept documented in the completed Wave 3 research.

Required engineering modes:

    WeightedFar
        production default

    LinearAverage
        reference / diagnostic

Optional diagnostic-only modes:

    Min
    Max

These are not end-user settings.

They exist to prove the production reduction during engineering.

Zero/background samples are ignored.

If no valid sample exists:

    output 0

======================================================================
27. NATIVE NORMAL DECODE
======================================================================

Wave 3 uses ONLY:

    NORMAL_MASK_CURRENT.RG

RT2.B remains unresolved.

RT2.A has unrelated public SSR evidence.

Neither B nor A is required for Wave 3 geometry normals.

The shared native normal decoder must match the already-proven repository /
public Skyrim behavior.

Current exact validated repository form:

    float3 DecodeNativeNormal(float2 encoded)
    {
        float2 e = encoded - 0.5;

        float nz =
            clamp(
                8.0 * dot(e, e) - 1.0,
                -1.0,
                1.0);

        float q =
            sqrt(
                max(
                    8.0 - 8.0 * nz,
                    0.0));

        float3 n =
            float3(
                e * q,
                nz);

        return normalize(n);
    }

This helper must exist once in shared Wave 3 shader code.

Do not create multiple slightly different normal decoders.

======================================================================
28. WORLD NORMAL HISTORY
======================================================================

Native decoded normal is expressed in the current camera/view frame.

Do NOT store that raw view-space normal as cross-frame history.

Required flow:

    native RG
    ->
    decode current view-space normal
    ->
    transform direction through CameraViewInverse
    ->
    normalize
    ->
    encode world normal
    ->
    store history

Previous history therefore holds a camera-independent surface orientation.

Temporal comparison:

    dot(currentWorldNormal, previousWorldNormal)

not:

    dot(currentViewNormalThisFrame, previousViewNormalLastFrame)

======================================================================
29. WORLD NORMAL HISTORY FORMAT
======================================================================

Primary format:

    R8G8_UNORM

Encoding:

    conventional octahedral unit-vector encoding for GZFX-owned world normals

This is a GZFX history format.

It is not the Skyrim native normal encoding.

The distinction must remain explicit:

    Skyrim native normal:
        proprietary/native two-channel decode described above

    GZFX previous world normal:
        GZFX-owned octahedral encode/decode

If the target D3D11 device reports inadequate typed UAV support for the
R8G8_UNORM write path:

    allowed correctness fallback:
        R16G16_FLOAT world-normal encoding

That fallback must be logged.

Do not silently change formats.

31. GLOBAL HISTORY INVALIDATION
======================================================================

Hard-reset history on at least:

1. no valid prior history / first valid frame
2. ResizeBuffers success
3. actual render resource size change
4. device generation change
5. surface generation change
6. frame discontinuity:
       currentFrame != lastCompletedFrame + 1
7. world/load interruption observable through renderer continuity
8. world inactive -> active reentry
9. conservative interior <-> exterior transition
10. native semantic generation change for:
       depth
       motion
       normal
       camera
11. non-finite or invalid camera data
12. camera cut / teleport
13. invalid dynamic-resolution metadata
14. temporal shader/resource rebuild changing the signal
15. explicit developer reset

    current ratio is valid
    previous ratio is valid
    resource dimensions are unchanged
    previous mapping remains valid

32. ENVIRONMENT TRANSITION POLICY
======================================================================

0.0.20 determines environment from completed-frame renderer behavior.

At AfterOpaqueWorldMRT, the current frame may not yet have completed enough
work to classify itself as exterior/interior.

Therefore Wave 3 must not pretend it has a future classification.

Required initial policy:

- carry the last completed environment token;
- associate history with the environment in which it was completed;
- if the new frame later proves an environment transition, invalidate history;
- renderer discontinuity / frame-gap / camera-cut signals should already fail
  closed on many load transitions;
- begin conservative: interior <-> exterior transitions reset;
- only relax this later if field evidence proves continuity safe.

No SKSE event dependency is permitted.

======================================================================
37. HISTORY ALLOCATION / DYNAMIC RESOLUTION
======================================================================

Allocate history textures at the native full resource dimensions.

Track active current/previous regions separately.

Let:

    resourceSize =
        full texture dimensions

    currentRatio =
        DynamicResolutionParams1.xy

    previousRatio =
        DynamicResolutionParams1.zw

Then:

    currentActiveSize =
        round(resourceSize * currentRatio)

    previousActiveSize =
        round(resourceSize * previousRatio)

For a current physical pixel p inside currentActiveSize:

    currentLogicalUV =
        (p + 0.5) / currentActiveSize

Equivalent current texture coordinate:

    currentDRUV =
        currentRatio * currentLogicalUV

which is also equivalent to:

    (p + 0.5) / resourceSize

Native motion is applied in LOGICAL normalized screen space:

    previousLogicalUV =
        currentLogicalUV + motion.xy

Bounds test:

    0 <= previousLogicalUV.x <= 1
    0 <= previousLogicalUV.y <= 1

Then:

    previousDRUV =
        previousRatio * previousLogicalUV

Use previousDRUV to sample previous history.

This distinction must be synthetic-tested.

======================================================================
39. TEMPORAL GEOMETRY PER-PIXEL FLOW
======================================================================

For each active current pixel:

1. read current view-space depth from hierarchy mip0

2. if current depth == 0:
       write invalid geometry
       confidence = 0
       stop

3. read native normal RG
   decode native view normal
   transform to current world normal
   normalize

4. write current geometry regardless of temporal acceptance:
       current linear depth
       current world normal

5. if global history is invalid:
       confidence = 0
       stop temporal reuse

6. compute current logical UV

7. sample native motion at currentDRUV

8. compute:
       previousLogicalUV =
           currentLogicalUV + motion.xy

9. reject if previousLogicalUV is out of logical [0,1]

10. compute previousDRUV from PREVIOUS ratio

11. gather previous:
       linear depth
       world normal
       confidence

12. run cheap depth rejection

13. if still valid:
       reconstruct current world position
       reconstruct previous world position

14. run world-position rejection

15. run world-normal rejection

16. if accepted:
       update confidence / accumulation

17. if rejected:
       hard reject or soft decay according to mismatch class

18. write capture masks if manual capture is armed

======================================================================
40. BILINEAR PREVIOUS GEOMETRY REPROJECTION
======================================================================

History sampling must be bilinear.

A manual four-tap gather is the preferred baseline because it lets GZFX
control how different geometry fields are combined.

Depth:

    bilinear weighted float depth

World normal:

    decode each of four oct normal taps
    weighted sum
    normalize

Confidence:

    bilinear weighted confidence

Invalid geometry taps must not silently pollute valid taps.

The implementation should renormalize weights over valid depth samples.

If no valid previous geometry tap contributes:

    history reject

Nearest-neighbor history lookup is not the Wave 3 production baseline.

======================================================================
41. DEPTH DISOCCLUSION
======================================================================

Use a layered rejection sequence.

Engineering parameter:

    DepthDisocclusion

Initial seed:

    0.02

This is field-tunable.

A. CHEAP EARLY DEPTH REJECT

Concept:

    abs(currentDepth - previousDepth)
    >
    currentDepth * DepthDisocclusion * 3

If true:

    reject before expensive world reconstruction

B. WORLD-POSITION VALIDATION

Reconstruct:

    current world position
    previous world position

using the corresponding frame camera data.

Movement threshold:

    movementThreshold =
        currentDepth * DepthDisocclusion

Accept geometry only when:

    distance(
        currentWorldPosition,
        previousWorldPosition)
    <
    movementThreshold

The exact multiplier may be tuned from Wave 3 evidence.

The architecture does not change.

======================================================================
42. WORLD-POSITION RECONSTRUCTION
======================================================================

Current world reconstruction uses:

    current camera projection/inverse view
    current logical UV
    current view-space depth
    current CameraPosAdjust convention

Previous world reconstruction uses:

    previous frame camera data
    previous logical UV
    previous linear depth
    previous CameraPosAdjust convention

The implementation must not mix current and previous camera transforms.

A shared helper must own this math.

Synthetic CI must include a known camera translation test proving that
reprojected previous geometry returns to the same world position.

======================================================================
43. NORMAL DISOCCLUSION
======================================================================

After depth/world-position validation:

    normalAgreement =
        dot(
            currentWorldNormal,
            previousWorldNormal)

Initial engineering threshold seed:

    0.75

Accept normal geometry when:

    normalAgreement >= threshold

This is deliberately a field-tunable seed.

The compact motion field run must report normal rejection percentage and
confirm the threshold is not rejecting ordinary smooth surfaces wholesale.

Depth and world-position remain primary validation.

Normal rejection is an additional quality gate.

======================================================================
44. GLOBAL INVALIDATION VS PER-PIXEL DISOCCLUSION
======================================================================

Do not conflate these two concepts.

GLOBAL INVALIDATION:

    entire history is unsafe

Examples:

    camera cut
    frame gap
    resize
    load transition
    device generation change
    missing critical semantic
    camera invalid

Response:

    history weight = 0 everywhere
    reset generation / reason recorded

PER-PIXEL DISOCCLUSION:

    global history exists, but this previous pixel does not represent the
    same current surface

Examples:

    newly revealed geometry
    moving viewpoint exposes background
    geometry edge mismatch
    normal mismatch

Response:

    reject/decay that pixel only

======================================================================
45. HISTORY CONFIDENCE / ACCUMULATION
======================================================================

Initial maximum stable history:

    16 frames
On global reset:

    confidence = 0

On a valid accepted reprojection:

    confidence increases toward a motion-dependent maximum

On hard per-pixel rejection:

    confidence = 0

On marginal mismatch / soft decay:

    confidence decreases rather than necessarily dropping to zero

The manager must expose:

    historyLength
    historyWeight
    reprojectionValid
    resetReason

to diagnostics.

    invalidate broker caches
    invalidate camera resource generation
    invalidate hierarchy
    invalidate temporal histories
    rebuild deferred context
    reset all GPU query pools

======================================================================

    skip hierarchy
    skip temporal geometry
    reset dependent history
    bounded log

MISSING CAMERA

    skip hierarchy if reconstruction cannot be proven
    skip temporal
    bounded log

MISSING MOTION

    hierarchy may still build
    temporal reuse must be invalid
    current geometry may still be written if safe
    no stale motion fallback

MISSING NATIVE NORMAL

    hierarchy may still build
    normal-dependent temporal validation is unavailable
    do NOT silently substitute depth-derived normal as production truth
    temporal path must fail closed according to the bundle contract

VIEW CREATION FAILURE

    skip affected pass
    invalidate dependent history
    log HRESULT once/boundedly

Never crash Skyrim for a missing optional GZFX frame.

Never guess.

95. THREAD / LOCK SAFETY
======================================================================

Stage Scheduler callbacks are synchronous.

Current Signal behavior releases the scheduler mutex before invoking callbacks.

Preserve that property.

Semantic Authority query callbacks must not call back into the authority while
holding an authority mutex that would deadlock.

RendererExecutionService, broker, history manager and diagnostics should use
small ownership locks and avoid holding them across D3D11 calls where
unnecessary.

Do not introduce a global "renderer everything" mutex.

96. REENTRANCY / GZFX COMMAND LISTS
======================================================================

Executing a GZFX command list on the hooked immediate context can cause hook
observation.

The owned-pass tag must therefore be active BEFORE execution.

Hook behavior for GZFX-owned execution must be deterministic:

    native semantic classifier:
        ignore GZFX-owned pass mutation as native evidence

    pipeline cartography:
        record owned execution if useful
        do not call it unknown Skyrim work

    global statistics:
        may count GZFX work separately

    Stage Scheduler:
        must not recursively produce native stage boundaries from GZFX output

This is mandatory.

======================================================================
97. CAMERA CPU-SHADOW EDGE CASE
======================================================================

The camera candidate might be updated before its first b12 bind is recognized.

Therefore the provider should retain a small bounded record for recent
720-byte constant-buffer writes keyed by buffer identity.

Once a 720-byte buffer is seen at the required native slots:

    promote its already-captured current payload if frame-valid.

Do not retain arbitrary buffer payloads indefinitely.

Suggested bound:

    only 720-byte candidates
    current frame + immediately previous frame during acquisition
    evict everything else

After stable camera promotion:

    track the selected buffer directly.

A mere new frame does not create a new camera generation.

    deviceGeneration

Temporal history records the camera generation used to produce it.

Generation change causes conservative reset.
