======================================================================
9. SOURCE / HISTORY ROOT CAUSE
======================================================================

Current menu code still contains the receiver:
    gzfx::ui::SubmitDirectInputMouse(...)

Current exported compatibility entry:
    GZFX_SubmitMouseInput(...)

The current visible-pass harness still describes this as:
    "the same exported relative-mouse bridge used by the dinput8 proxy"

But the dinput8 proxy was retired in 0.0.31.

Historical working chain before proxy retirement:

    DirectInput8Create
      -> hook IDirectInput8::CreateDevice
      -> identify GUID_SysMouse
      -> hook mouse IDirectInputDevice8::GetDeviceState
      -> hook mouse IDirectInputDevice8::GetDeviceData
      -> feed deltas/buttons to GZFX_SubmitMouseInput
      -> while GZFX menu open, zero immediate mouse state
      -> while GZFX menu open, return zero buffered event count
      -> Skyrim camera does not consume the same mouse input

Relevant preserved commits:
    a12273f5a51fdd379d3b7b4c329fb3f50ed5d75a
        drive settings cursor/sliders from DirectInput mouse data

    bea3340ad0e9a2a52307295358e736f34e983dae
        bridge DirectInput mouse state into live GZFX menu

    0d2939e76c02f25770b1ff0e28b02c149fa7ff36
        capture and suppress Skyrim DirectInput mouse while GZFX menu is open

    8f3fabf02d3525173ed0994633dbc344fda5ae8b
        DirectInput packet diagnostics

    c3bdc3799e4147e976a615de1aea03d646711fb7
        slider test through exported DirectInput bridge

0.0.31 retired the GZFX dinput8 proxy as required by the one-DLL migration.

The menu-side DirectInput receiver remained, but the producer/capture layer was
not migrated into GZFX.dll.

That migration omission is the root cause of the current mouse regression.

======================================================================
10. WHY THE WNDPROC FALLBACK IS NOT SUFFICIENT
======================================================================

Current settings_menu.cpp subclasses the game HWND and handles:
    WM_MOUSEMOVE
    WM_LBUTTONDOWN / UP
    WM_INPUT

This can provide a fallback pointer source when Windows messages are available.

It does not guarantee ownership of Skyrim's DirectInput device.

The field result proves that Skyrim continues consuming mouse input while the
GZFX overlay is open.

The current menu diagnostic also shows no DirectInput packets.

Therefore the fix must restore DirectInput ownership/suppression at the source,
not merely add more WM_MOUSEMOVE handling.
