GZFX 0.0.31 SKSE SINGLE-DLL MIGRATION — FINDINGS
Date: 2026-11-04
Owner directive: replace the standalone proxy/bootstrap shell with current Steam AE SKSE integration and ship one GZFX DLL.

SCOPE
This is a bounded integration migration. It does not promote WaterDomain, PostTonemapPreUi, AfterShadowProduction, or alter the field-locked HDRReduction / BeforeTonemap / BeforeGlobalTAA / AfterGlobalTAA contracts.

CURRENT THREE-DLL SHELL
- d3d11.dll: system-name proxy, forwards System32 D3D11, loads GZFX.dll, captures primary renderer creation, installs ExitProcess shutdown.
- dinput8.dll: system-name proxy, forwards DirectInput, loads GZFX.dll, captures mouse input.
- GZFX.dll: actual renderer/framework.

KEY SOURCE FINDINGS
1. GZFX.dll already contains an independent D3D11 lifecycle front door in src/diagnostics/d3d11_lifecycle.cpp. It patches SkyrimSE.exe D3D11/DXGI imports and can attach the real device/context/swapchain to renderer_forensics.
2. renderer_forensics can arm its DXGI/D3D11 COM hooks before the real Skyrim renderer is created by resolving method targets through a temporary WARP device.
3. The settings menu already has an independent Win32/raw-input path (WndProc, WM_INPUT, WM_MOUSE*, GetAsyncKeyState). dinput8.dll is not the only usable menu-input path.
4. The proven clean-shutdown path currently lives in the d3d11 proxy. Removing that proxy requires moving ExitProcess interception into GZFX.dll or replacing it with an equally deterministic process-exit mechanism.
5. The current package and CI explicitly require three DLLs; build/package/workflow contracts must be changed together.
6. Current renderer semantics are valuable and must survive unchanged. The migration target is the loader/integration shell, not a renderer rewrite.

MIGRATION CONSEQUENCE
The proxy DLLs can be removed without discarding the GZFX renderer. SKSE can own plugin loading/lifecycle while GZFX retains direct D3D11/DXGI ownership for graphics work.

END FINDINGS
