======================================================================
1. PRODUCT INTENT
======================================================================

0.0.27 is NOT an ENB/ReShade compatibility wave.

ENB and ReShade were architecture references only.

GZFX remains:

    standalone;
    SKSE-free;
    Address-Library-free at runtime;
    independently implemented;
    intended to replace the graphics role of ENB + ReShade.

Runtime coexistence with ENB/ReShade is NOT an acceptance target for this wave.

The compatibility target IS:

    one GZFX renderer core across popular Skyrim SE/AE runtimes,
    including downgraded modding runtimes such as 1.5.97 and current 1.7.x.

The universal contract is:

    runtime-independent D3D11/DXGI renderer ownership first;
    optional version-specific Skyrim engine anchors second.

Unknown/new Skyrim runtimes must still receive the universal renderer core.
They must not be rejected merely because an engine-hook profile is absent.

4. LANE A — SAFE D3D11 GRAPHICS-FRONT-DOOR BOOTSTRAP
======================================================================

Add a second tiny root bootstrap:

    d3d11.dll

alongside the existing:

    dinput8.dll

dinput8.dll remains the input bridge.

d3d11.dll becomes a GRAPHICS BOOTSTRAP ONLY.

It must not contain renderer logic.

It must:

    load the real system d3d11.dll by absolute System32 path;
    forward the required D3D11 exports faithfully;
    perform no heavy work from DllMain;
    initialize GZFX only from an actual exported D3D11 API call;
    initialize after the real primary device creation succeeds but before the
    returned device/context/swapchain are returned to Skyrim;
    explicitly attach those returned objects to GZFX;
    preserve original HRESULT and returned objects.

Primary exported functions:

    D3D11CreateDevice
    D3D11CreateDeviceAndSwapChain

Core forwarding exports required by standard D3D11 proxy behavior:

    D3D11CoreCreateDevice
    D3D11CoreCreateLayeredDevice
    D3D11CoreGetLayeredDeviceSize
    D3D11CoreRegisterLayers

No ENB/ReShade chain support is required for 0.0.27 acceptance.

If another local d3d11.dll is already required by a user, that is outside this
wave's supported field configuration.

The package is intended to run GZFX standalone.

======================================================================
5. D3D11 BOOTSTRAP REENTRANCY / ORDERING
======================================================================

The bootstrap must avoid recursive initialization.

Required flow for first application D3D11CreateDevice[AndSwapChain]:

    d3d11 proxy export entered
    ->
    ensure real system d3d11.dll loaded
    ->
    call REAL system D3D11 creation
    ->
    receive successful device/context/swapchain
    ->
    initialize GZFX.dll exactly once
    ->
    explicit primary-object attach
    ->
    return original objects to Skyrim.

During GZFX initialization, renderer_forensics may create a temporary WARP
device to resolve method addresses.

If that call re-enters the proxy while GZFX initialization is already active:

    forward directly to real D3D11;
    do NOT recursively initialize GZFX;
    do NOT attach that temporary WARP device as primary.

Use an explicit thread-local or atomic initialization guard.

10. LANE F — HDR ROOT REPAIR
======================================================================

Current root logic requires the first reduction pass to read canonical MAIN_HDR.

This fails most interiors because interior rendering contains:

    MAIN_HDR
    ->
    same-frame full-resolution RGBA16F descendant
    ->
    640x360 reduction chain.

Add a bounded HDR ancestry concept.

Eligible reduction root may read:

A. canonical MAIN_HDR directly;

OR

B. a verified same-frame full-resolution RGBA16F descendant of MAIN_HDR.

Descendant proof must be structural and bounded:

    full-resolution;
    RGBA16F;
    produced after late-stage eligibility;
    consumes canonical MAIN_HDR or a previously verified full-res HDR descendant;
    same frame;
    short bounded ancestry depth.

Do not allow arbitrary graph reachability.

======================================================================
11. LANE G — HDR TRUE TERMINAL / BEFORETONEMAP REPAIR
======================================================================

Current bug:

    3x2 satisfies <=4x4
    ->
    detector commits complete
    ->
    actual 2x2 successor is ignored
    ->
    BeforeTonemap looks for the wrong identity.

Observed stable chain:

    40x23
    -> 10x6
    -> 3x2
    -> 2x2

The detector must not commit terminal state on the first <=4x4 resource.

Recommended bounded rule:

    continue a coherent descending RGBA16F dependency chain while a successor
    exists in the same late image-space region;

    prefer 2x2 or smaller as final terminal where the chain reaches it;

    if 3x2 is followed by a coherent 2x2 successor, terminal becomes 2x2.

For this field family the true terminal should become:

    2x2

Then BeforeTonemap/full-res transition should be eligible when a later pass:

    reads the final tiny HDR/adaptation terminal;
    writes full-resolution R8G8B8A8_UNORM;
    lies immediately upstream of the locked global TAA family.

Stable field corroboration:

    pre-TAA full-res PS:
        0x99D22A3D198A3B69

Again, hash is corroboration only.

17. UNIVERSAL RUNTIME POLICY
======================================================================

GZFX product support is defined by two levels.

LEVEL 1 — UNIVERSAL RENDERER CORE

Expected to operate across supported Skyrim SE/AE builds because it depends on
Microsoft D3D11/DXGI contracts rather than Skyrim executable offsets.

Includes:
    renderer bootstrap
    resource/shader identity
    semantic resource graph
    TAA/HDR structural contracts
    GZFX graphics features
    Present lifecycle

LEVEL 2 — OPTIONAL ENGINE SEMANTIC PROFILE

Adds verified executable-specific landmarks where safely known.

May vary by:
    1.5.97
    1.6.x
    1.7.x

Absence of Level 2 must not disable Level 1.

This is the basis for Nolvus/downgrade/current-runtime compatibility.
