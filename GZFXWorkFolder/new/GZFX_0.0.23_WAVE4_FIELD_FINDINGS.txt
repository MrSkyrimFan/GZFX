======================================================================
1. EXECUTIVE VERDICT
======================================================================

The 0.0.23 field run is valid and highly informative.

The core architecture WORKS.

Wave 4 is successfully:
- computing full-resolution GTAO-inspired visibility from the Wave 3 hierarchy;
- using the native Skyrim normal/motion/camera foundation;
- producing spatially coherent visibility;
- temporally filtering the signal;
- replacing Skyrim SAO_FILTERED at AfterStockAO;
- allowing Skyrim's own Ambient Screen-Space Composite to consume the result;
- preserving the Wave 1/2/3 renderer foundation.

There is no evidence that the new architecture itself needs to be abandoned.

However, Wave 4 should NOT be closed yet.

Two real issues remain:

1. PERFORMANCE IS TOO EXPENSIVE FOR THE LONG-TERM PRODUCT TARGET.

   The raw GTAO pass alone averages roughly 2.4-3.4 ms at 2560x1440.
   Mean total Wave 4 GPU cost from the capture windows is roughly 3.69 ms.
   P95 total windows range from 3.08 ms to 9.52 ms.

   This is above the research/blueprint target and too expensive for one
   effect if GZFX still needs indirect radiance, reflections, volumetrics,
   shadows, water and post/HDR work later.

2. THE VISIBILITY SIGNAL IS PROBABLY TOO AGGRESSIVE FOR THE FIRST PRODUCT
   TUNING.

   Across 13 captures:

       mean stock SAO visibility ~= 0.9508
       mean GZFX visibility      ~= 0.8459

   GZFX is therefore about 0.105 lower on average as a visibility signal.

   In the downsampled diagnostic comparisons, GZFX is meaningfully lower than
   stock in about 70% of pixels, higher in about 9%, and nearly equal in about
   21%.

   This does NOT mean the final image is literally 10.5% darker, because the
   stock ambient composite determines the final lighting response.

   It DOES mean the GZFX AO term is significantly more occluding and broader
   than Skyrim's stock term.

The good news is that the GZFX signal is not simply "gray everywhere."

Across all captures:

    average fraction > 0.95 visibility ~= 42.8%
    average fraction < 0.50 visibility ~= 7.9%

The images show real geometric structure around terrain, trees, buildings,
actors and contact regions.

So the current issue looks like:

    TOO MUCH / TOO EXPENSIVE

not:

    WRONG PIPELINE / BROKEN SIGNAL.

Owner intervention is not technically required before research.

    semantic frame = 8800

but no separate Wave4 manual capture completes immediately.

The next Wave4 manual capture is:

    Wave4 manual0011 frame 9023

while another semantic request occurred at:

    frame 8961

This is consistent with the current Wave4 capture mechanism:

- one Wave4 capture can remain armed while Mode 1/2 is not actively producing
  Wave4 frames;
- while that capture is pending, another RequestManualCapture is not queued as
  a second pending request;
- the old request completes later when Wave4 resumes.

This is a DIAGNOSTIC TOOLING ISSUE.

It is not evidence of Wave4 renderer skips.

Final Wave4 runtime reports:

    skips=0

    replace the single pending boolean/slot with a tiny bounded capture-request
    queue or sequence counter.

======================================================================

Repository owner clarification after DATA review:

The 0.0.23 field run is NOT an artistic-quality acceptance test.

Mode 2 was intentionally untuned.

Current GZFX settings/sliders materially alter darkness, strength and visual
quality. Higher settings can intentionally make the effect look worse.

Therefore:

    current Mode 2 appearance
    !=
    final GZFX quality target

The correct conclusion from this run is:

    GZFX CAN OWN THE SAO / AMBIENT-VISIBILITY STACK.

Do NOT use this untuned build to decide whether final GZFX AO is aesthetically
good or bad.

The project's current priority is broader:

    discover and understand Skyrim's complete graphics pipeline
    ->
    own the full renderer stack
    ->
    only then perform serious artistic tuning / quality optimization.

PERFORMANCE INTERPRETATION IS ALSO REVISED.

The current forensic/test build performs extensive active logging and writes
large amounts of evidence to disk while Skyrim is running.

Observed FPS loss and timing spikes therefore contain unknown instrumentation
overhead.

Current timing evidence is useful for identifying rough relative hot spots,
but it is NOT accepted as clean production-performance evidence.

Specifically:

    0.0.23 measured cost
    !=
    final no-logging GZFX production cost.

A later quiet/performance build with diagnostics disabled is required before
making release-performance claims.

Accordingly, replace the earlier simplified verdict:

    "visual tuning needs work, performance FAIL"

with the controlling project verdict:

    ARCHITECTURAL OWNERSHIP = PASS

    ARTISTIC QUALITY = NOT YET A PROJECT GATE

    PRODUCTION PERFORMANCE = NOT YET CLEANLY MEASURED

    FULL RENDERER / STACK DISCOVERY = CURRENT PRIORITY

The owner also directs that the manual capture system should no longer be the
primary discovery mechanism.

Next instrumentation direction:

    XForge-style renderer telemetry listener

Goals:

- continuously record the renderer facts GZFX needs while the user simply
  plays normally;
- capture modes, environments, stages, semantic identities, resource
  generations/contracts, timing, transitions and ownership state;
- move expensive disk writing off the render thread;
- make discovery sessions much less dependent on manual capture timing;
- allow future DATA review from one uploaded telemetry session.

Research phase may now proceed under this clarification.
