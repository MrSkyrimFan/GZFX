15. WHY THE 0.0.27 ANCESTRY REPAIR FAILED IN THE REAL GAME
======================================================================

Current source:

    src/render/semantic_authority.cpp
    ObserveHdrReductionLocked()

0.0.27 added:

    hdrReductionSourceIdentity
    hdrFullResAncestryDepth

and allows up to three full-resolution HDR descendants.

However, ancestry discovery occurs only while:

    hdrReductionStep == 0

The real Skyrim late stack contains an earlier plausible 640x360 reduction
candidate before the final real reduction root.

The detector can therefore enter:

    hdrReductionStep = 1

on that false earlier root.

Once that happens:

    full-resolution ancestry discovery is no longer executed.

The later restart logic allows a fresh root only when the new downsample reads:

    hdrReductionSourceIdentity

or, if that is still zero:

    canonical MAIN_HDR.

On the 2,640 affected interior frames, the sequence is effectively:

    canonical MAIN_HDR
    ->
    earlier plausible false reduction root
        detector enters step 1
    ->
    later real full-resolution interior HDR transform
        PS 0x1066E41D475505A3
        writes 0x251E9627950
    ->
    real 640x360 HDR root
        PS 0xF026B1E764F561A5
        reads 0x251E9627950
    ->
    160x90
    ->
    40x23
    ->
    10x6
    ->
    3x2
    ->
    2x2
    ->
    downstream exposure/reconstruction
    ->
    full-res 0x99D22A3D198A3B69
    ->
    global TAA

Because the full-resolution descendant appears AFTER the false root was already
latched, the current ancestry state is not updated to 0x251E9627950.

The fresh-root restart then asks whether the real 640x360 root reads canonical
MAIN_HDR.

It does not.

It reads 0x251E9627950.

Therefore restart fails and semantic HDRReduction never reaches the physically
present 2x2 terminal.

On the 241 interior frames where the real root reads canonical MAIN_HDR
directly, restart succeeds and both HDRReduction and BeforeTonemap fire.
