6. DIRECT3D 11 STRUCTURAL BASIS REMAINS SOUND
======================================================================

Microsoft documents PSSetShaderResources and OMSetRenderTargets as explicit
resource-view bindings on the D3D11 context.

Relevant documented behavior includes:

    PSSetShaderResources binds concrete SRV interfaces;

    OMSetRenderTargets binds concrete RTV/DSV interfaces;

    overlapping read/output bindings are nulled to prevent one subresource from
    being simultaneously read and written through conflicting bind points.

References:

    Microsoft Learn:
    ID3D11DeviceContext::PSSetShaderResources

    https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-pssetshaderresources

    ID3D11DeviceContext::OMSetRenderTargets

    https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-omsetrendertargets

Research consequence:

    a GZFX-observed read of resource A followed by a write to resource B is a
    meaningful D3D resource-lineage edge;

    GZFX does not require shader-name guessing to establish bounded HDR
    ancestry.

This supports the current identity/shape/dependency-based detector.

8. CURRENT ISHDR SHADER EVIDENCE
======================================================================

Current Community Shaders package/Shaders/ISHDR.hlsl contains two relevant
families:

    DOWNSAMPLE
    BLEND

The DOWNSAMPLE branch:

    samples the image;
    reduces it;
    has luminance variants;
    supports adaptation with AdaptTex / DOWNADAPT.

The BLEND branch:

    reads:
        ImageTex
        BlendTex
        AvgTex

    obtains:
        avgValue

    applies exposure behavior using:
        avgValue.y / avgValue.x

    then performs tonemap behavior including:
        Reinhard
        or Hejl-Burgess-Dawson

    and also applies:
        bloom
        saturation
        tint
        contrast
        cinematic intensity
        fade

before emitting the full-resolution image.

This independently matches the GZFX field interpretation:

    tiny HDR reduction/adaptation terminal
    ->
    full-resolution HDR tonemap/blend/cinematic image-space pass
    ->
    global TAA.

======================================================================
9. IS "BEFORETONEMAP" TOO STRONG A NAME?
======================================================================

No, provided the project documents the boundary precisely.

The Skyrim pass is not a mathematically pure one-operation tonemapper.

It is a compound image-space pass whose public reverse-engineered name is:

    HDRTonemapBlendCinematic

and whose shader performs tonemap plus bloom/cinematic/fade work.

Therefore the GZFX boundary name:

    BeforeTonemap

is acceptable shorthand for:

    immediately before Skyrim's HDR tonemap/blend/cinematic image-space pass.

Do NOT document it as:

    "before every possible color transform"
    or
    "before all post processing."

It is a precise scheduling landmark around the vanilla HDR tonemap family.

A future public API may optionally describe the long form in documentation,
but renaming the enum is not justified.

10. HDRREDUCTION SEMANTIC SCOPE
======================================================================

HDRReduction should be defined as:

    completion of the verified MAIN_HDR-descended reduction/adaptation spine
    at its true <=2x2 terminal for the current active scene frame.

It does NOT mean:

    all HDR work is complete;
    all bloom work is complete;
    the frame is tonemapped;
    the frame is ready for UI;
    every tiny RGBA16F chain is HDR adaptation.

The structural contract remains:

    bounded canonical MAIN_HDR ancestry;
    bounded verified full-resolution HDR sibling sources;
    one coherent descending chain;
    true <=2x2 terminal.

This precise definition is supported by both field evidence and independent
public Skyrim shader evidence.

17. POSTTONEMAPPREUI — STILL NOT PROMOTABLE
======================================================================

DO NOT PROMOTE.

Historical Research Passes 6, 7 and 9 required an independently justified UI
boundary, not merely TAA completion or a late full-resolution sink.

Current public Community Shaders source still supports that caution.

It hooks:

    MenuManagerDrawInterfaceStart

and current comments explicitly describe that point as the start/duration of
menu interface rendering.

HDR Display uses that hook to redirect the framebuffer for vanilla UI capture.

This is a credible pre-UI semantic anchor.

However GZFX's live field runtime is:

    1.7.104

and GZFX currently has no verified executable PRE_UI profile for 1.7.104.

The current field DATA therefore does NOT contain the engine-level UI bracket
that Research Pass 9 required.

Do not infer PostTonemapPreUi from:

    AfterGlobalTAA alone;
    one shader hash;
    one final full-resolution sink;
    proximity to Present.
