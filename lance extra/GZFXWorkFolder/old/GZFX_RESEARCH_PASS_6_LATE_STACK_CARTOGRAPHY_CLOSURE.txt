======================================================================
1. RESEARCH VERDICT
======================================================================

The next engineering wave should be:

    0.0.25-late-stack-cartography-closure

It is NOT a graphics-quality wave.

It should do four things coherently:

1. instrument Skyrim-created D3D11 deferred contexts while commands are being
   RECORDED, then associate the recorded pass stream with the immutable
   command list returned by FinishCommandList and finally with the real frame
   where ExecuteCommandList plays it back;

2. repair compact telemetry for explicit operations so CopyResource,
   CopySubresourceRegion, ResolveSubresource, ClearRTV, ClearDSV, ClearUAV and
   GenerateMips carry their TRUE explicit resource operands instead of stale
   bound-state resource lists;

3. remove silent concrete-read truncation by recording true total access
   counts and a larger bounded identity set with explicit overflow flags;

4. promote only the late Stage Scheduler landmarks that current field evidence
   plus independent public Skyrim shader evidence can support:
       HDRReduction
       BeforeTonemap
       BeforeGlobalTAA
       AfterGlobalTAA

Do NOT promote:
    WaterDomain
    PostTonemapPreUi
    AfterShadowProduction

yet.

======================================================================
2. WHY COMMAND LISTS CANNOT BE INSPECTED AFTER THE FACT
======================================================================

Microsoft's D3D11 API exposes ID3D11CommandList as an immutable playback
object.

A command list is produced by:

    deferredContext->FinishCommandList(...)

and later executed with:

    immediateContext->ExecuteCommandList(...)

ID3D11CommandList itself exposes no enumeration API for its recorded Draw,
Dispatch, copy, state-setting, or binding commands.

Therefore this approach is NOT viable:

    ExecuteCommandList observed
    ->
    inspect command list object
    ->
    enumerate internal draws.

There is no supported API to do that.

The commands must be observed while they are recorded on the deferred
ID3D11DeviceContext.

======================================================================
3. CORRECT DEFERRED-CONTEXT OBSERVATION POINT
======================================================================

Microsoft explicitly documents:

    CreateDeferredContext
    ->
    use deferred ID3D11DeviceContext to set state / Draw / Dispatch / copy
    ->
    FinishCommandList
    ->
    immutable ID3D11CommandList
    ->
    ExecuteCommandList on the immediate context.

Therefore GZFX should instrument:

    ID3D11Device::CreateDeferredContext

and attach a context-specific tracker to every returned deferred context.

This must happen BEFORE Skyrim records the command list.

======================================================================
4. CONTEXT CREATION HOOK STRATEGY
======================================================================

Current Renderer Forensics already installs global MinHook detours using a
temporary D3D11 device/swap chain to resolve implementation method addresses.

The same startup resolver can safely expose the implementation address of:

    ID3D11Device::CreateDeferredContext

from the temporary device vtable.

Recommended strategy:

- extend Renderer Forensics Targets with createDeferredContext;
- install one MinHook detour during the same Arm() transaction as
  Present/Present1/ResizeBuffers;
- call the original CreateDeferredContext;
- if successful, attach the returned context to a dedicated
  deferred-context cartographer.

This is preferable to turning the old experimental full device-vtable
creation interception lane on globally.

Only the one API needed for this wave becomes field-active.

======================================================================
5. DEFERRED CONTEXTS NEED THEIR OWN STATE
======================================================================

D3D11 deferred contexts are specifically designed for recording on worker
threads.

Multiple deferred contexts can exist simultaneously.

Therefore GZFX MUST NOT reuse the immediate-context global CurrentState object.

Each deferred context needs:

    context identity
    context generation
    original vtable
    replacement vtable
    current graphics/compute binding state
    current command-list recording generation
    compact recorded pass runs
    explicit operation records
    counters / overflow health

A global mutex around a context registry is acceptable for this forensic
build, but each context should own its own state so two worker threads cannot
contaminate each other.

======================================================================
6. DEFERRED CONTEXT TYPE
======================================================================

Microsoft documents ID3D11DeviceContext::GetType and
D3D11_DEVICE_CONTEXT_DEFERRED.

Attachment should verify:

    context->GetType() == D3D11_DEVICE_CONTEXT_DEFERRED

before replacing a vtable.

This avoids accidentally re-hooking the primary immediate context through the
deferred path.

======================================================================
8. FINISHCOMMANDLIST IS THE OWNERSHIP SEAL
======================================================================

Microsoft documents that FinishCommandList creates the immutable command list
containing commands recorded by the deferred context.

At successful FinishCommandList:

GZFX should assign:

    commandListGeneration

and seal:

    deferredContextGeneration
    recordingGeneration
    recorded compact pass runs
    explicit resource operands
    restoreDeferredContextState flag

to the returned command-list identity.

This record is now immutable in GZFX just as the real D3D11 command list is.

Do not use raw pointer identity alone as lifetime proof.

The 0.0.24 field data showed heavy pointer reuse.

Use:

    canonical pointer
    +
    monotonic GZFX generation.

======================================================================
9. FINISHCOMMANDLIST STATE SEMANTICS
======================================================================

Microsoft documents:

RestoreDeferredContextState = FALSE:
    deferred context returns to default state after FinishCommandList.

TRUE:
    the deferred context's pre-Finish state is restored.

The tracker must mirror that behavior:

FALSE:
    reset tracked CurrentState after sealing the list.

TRUE:
    preserve the tracked CurrentState.

Each GZFX recording generation still starts after the previous
FinishCommandList boundary.

This matches Microsoft's statement that each FinishCommandList records the
commands since the prior FinishCommandList call.

======================================================================
10. NESTED EXECUTECOMMANDLIST ON A DEFERRED CONTEXT
======================================================================

Microsoft allows ExecuteCommandList on another deferred context, producing a
merged deferred command list.

Therefore the deferred hook must handle:

    deferredContext->ExecuteCommandList(existingList,...)

Recommended behavior:

- look up the GZFX-sealed existing command-list record;
- append/expand its compact run stream into the current deferred recording,
  preserving a nested-list marker;
- apply D3D11 restore-state semantics to the deferred tracker;
- if the existing list was not observed by GZFX, record an opaque nested-list
  marker rather than fabricating contents.

This prevents an invisible hole if Skyrim merges lists before main playback.

======================================================================
11. IMMEDIATE EXECUTE IS THE FRAME JOIN
======================================================================

At the existing primary immediate-context HookExecuteCommandList:

if command list is Skyrim/unknown-owned:

    query deferred cartography record.

If found:

    attach its recorded runs to:
        current GZFX frame
        immediate execute ordinal
        command-list generation
        deferred-context generation

and emit them to telemetry.

If not found:

    preserve an opaque_command_list event.

This is where recording-time work becomes a real frame-ordered renderer
stream.

======================================================================
12. DEFERRED RECORDING THREAD VS WRITER THREAD
======================================================================

The deferred-context hooks may run on arbitrary Skyrim worker threads.

They MUST NOT write files.

They may:

    update their context-local CPU state
    append compact POD runs
    query view/resource identities through COM GetResource/GetDesc
    calculate hashes
    seal a bounded list record

They must not call the immediate context.

The existing telemetry writer thread remains the only new file-writing lane.

======================================================================
13. BOUNDED MEMORY / FAILURE BEHAVIOR
======================================================================

A malicious or pathological command list must not consume unlimited memory.

Recommended initial bounds:

per deferred context active recording:
    65,536 compact runs

sealed command-list registry:
    256 live records

per sealed list:
    record overflow flag
    original pass count
    retained run count

If a bound is exceeded:

    do not block Skyrim
    retain first/last/aggregate evidence
    increment dropped/overflow diagnostics
    mark list incomplete

Never fail rendering because telemetry overflowed.

======================================================================
14. EXPLICIT OPERATION LINEAGE REPAIR
======================================================================

0.0.24 continuous compact telemetry calls generic pass-state snapshot logic for
copy/resolve/clear operations.

That is wrong for exact lineage.

A CopyResource row must carry:

    explicit source resource
    explicit destination resource

not whatever SRVs/RTVs happened to remain bound.

A ClearRTV row must carry:

    resource behind the clear's RTV

not current OM render targets.

Required explicit access rules:

CopyResource:
    read  = source
    write = destination

CopySubresourceRegion:
    read  = source + source subresource
    write = destination + destination subresource

ResolveSubresource:
    read  = source + source subresource
    write = destination + destination subresource
    format preserved

ClearRTV:
    write = RTV resource + view range

ClearDSV:
    write = DSV resource + flags + view range

ClearUAV:
    write = UAV resource + view range

GenerateMips:
    read/write = SRV resource / mip chain

ExecuteCommandList:
    no fake bound-state resource lineage;
    contents come from the sealed deferred-list record when available.

This repair applies to immediate and deferred telemetry.

======================================================================
15. CONCRETE ACCESS TRUNCATION REPAIR
======================================================================

0.0.24 retains only eight concrete read IDs.

71.69% of late rows hit that ceiling.

Simply increasing from 8 to 16 without reporting overflow would repeat the
same mistake.

0.0.25 should record:

    total unique read count
    total unique write count
    retained read count
    retained write count
    read overflow bool
    write overflow bool

Recommended retained concrete capacity:

    reads: 24
    writes: 12

The full read/write binding hashes remain.

This creates explicit evidence when a list is not exhaustive.

No future DATA report may interpret a capped list as complete without checking
overflow.

18. GLOBAL TAA IDENTIFICATION — EXTERNAL CONFIRMATION
======================================================================

The field data found a stable full-resolution pass that:

    reads current full-resolution RGBA8
    reads a ping-pong full-resolution RGBA8 history resource
    reads native motion
    reads depth
    produces two full-resolution RGBA8 outputs
    has perfect feedback-history alternation
    occurs before every normal deferred command-list execution.

Public Community Shaders' ISTemporalAA shader is a decompile-transcription
signpost for Skyrim's image-space TAA path.

It declares exactly six pixel inputs:

    t0 currentFrameTex
    t1 historyTex
    t2 velocityTex
    t3 depthTex
    t4 maskTex
    t5 alphaTex

and two outputs:

    Color
    Feedback

It also reprojects history using velocity.

This independently matches the GZFX field signature extremely closely.

Research conclusion:

    the observed full-resolution two-output temporal family can now be treated
    as the Skyrim global ISTemporalAA family for Stage Scheduler purposes,
    provided the runtime detector uses RESOURCE/SHAPE/DEPENDENCY invariants,
    not hardcoded shader pointer or field ordinal.

Authorized promotions:

    BeforeGlobalTAA
    AfterGlobalTAA

19. GLOBAL TAA RUNTIME DETECTOR
======================================================================

Do NOT hardcode the observed shader addresses.

Detect a candidate Draw/Dispatch using current Semantic Authority state:

- two full-resolution R8G8B8A8_UNORM outputs;
- reads MAIN_DEPTH_CURRENT;
- reads MOTION;
- reads at least two full-resolution R8G8B8A8_UNORM SRVs;
- occurs after the tonemap/current-output candidate in the frame;
- first such qualifying family per frame only.

Before execution:

    signal BeforeGlobalTAA.

After successful draw/dispatch observation:

    signal AfterGlobalTAA.

The next field listener session validates one pair per active frame and the
expected history ping-pong.

21. HDR REDUCTION DETECTOR
======================================================================

Use a per-frame state machine based on output resource shapes.

At minimum detect the suffix:

    40x23 RGBA16F
    ->
    10x6 RGBA16F
    ->
    3x2 RGBA16F
    ->
    2x2 RGBA16F

with descending dimensions and one qualifying stage per frame.

Exact dimensions scale with current resolution, so production detector should
prefer ratio/small-surface rules where practical and use exact 2560x1440
values only in the synthetic CI fixture.

After the final 2x2 output is written:

    signal HDRReduction / AfterExecution.

The next full-resolution R8G8B8A8_UNORM image-space output that consumes the
reduction/adaptation family and precedes the TAA family becomes:

    BeforeTonemap / BeforeExecution

for scheduling purposes.

Because the enum currently has no AfterTonemap boundary, do not invent one.

The TAA boundary supplies the next locked landmark.
